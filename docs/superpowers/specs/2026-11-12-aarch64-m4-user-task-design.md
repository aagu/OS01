# AArch64 M4 正式用户任务与 ELF 装载设计

## 目标与范围

用现有 BSP 调度器创建、运行、切换和回收真正的 EL0 任务。任务持有第一块实现的私有 `mm`，ELF 映像装入该根，调度器按任务安装 `TTBR0`。任务可以用最小的 SVC 入口主动让出、替换映像或退出。成功替换保留任务身份和内核栈，失败后从旧映像继续执行。

首版运行于现有 QEMU virt 的 Cortex-A53 配置，限制在单核 BSP、ASID 0、普通 4 KiB 页、静态内存 ELF、整数寄存器和协作调度。EL0 IRQ 可正常分派和返回，定时器只记账。正式 syscall ABI、用户指针复制、VFS 路径装载、`argv/envp/auxv`、动态链接、TLS、FP/SIMD 上下文、信号、父进程等待、活动根改表、抢占和 SMP 用户调度分属后续工作。AArch64 普通镜像编译运行期机制，仍按现有 `OS01_HAS_USERSPACE` 启动契约进入 idle。自测变体提供初始 ELF 和启动调用方。

## 方案选择

M4.7 的内核线程代跑方案适合验证一次 EL0 往返。正式任务采用 `PF_PROCESS`、私有 `task->mm`、专有内核栈和调度上下文。首入和异常恢复共用现有 AArch64 寄存器帧恢复逻辑。第一块的 M3 接口继续负责叶子映射，任务映像持有叶子页的清单。

采用内核提供的不可变映像目录作为首个装载源。启动和替换使用同一个内存 ELF 构造器，SVC 传目录索引。接入现有 x86 文件装载或通用 syscall 分派需要先处理 VFS、用户复制和 x86 页表耦合，留给后续块。最小 SVC 选择器属于本阶段的内部接口。

## 映像构造与所有权

- 目录及其中的字节和长度在任务存活期间保持有效，由内核提供。目录索引在读取目录项前检查。索引无效返回 `-EINVAL`，ELF 格式或布局不合规返回 `-ENOEXEC`，资源不足返回 `-ENOMEM`。继续传递用户 `mm` 运行期门控的错误。
- 复用共享 ELF 布局校验及现有 AArch64 静态装载规则。接受 little-endian ELF64、`EM_AARCH64`、`ET_EXEC`，版本为 1。限制 32 个程序头和 16 个装载页。检查头表、文件段和 VA 的算术边界，程序头先复制到对齐对象。拒绝动态段、解释器、TLS 段、重叠页、非页对齐的装载 VA、不可读段、W+X 和未落在 RX 文件字节内的 4 字节对齐入口。遵守现有布局验证器的用户地址包络和 `p_align` 约束。装载页上限独立于栈页。
- 构造阶段使用未发布的新 `mm`。每页先清零，再复制文件覆盖部分，BSS 和最后一页的余量保持为零。按段映射 RO/X、RO/NX 或 RW/NX，并在首次执行前完成已有的 D-cache 清理和 I-cache 同步。用户栈为 `[0x20400000, 0x20401000)` 的一页 RW/NX，下面一页为未映射 guard。初始 SP 为栈顶，PC 为 ELF 入口，GPR 和 NZCV 清零。用户态开启 IRQ，D/A/F 保持屏蔽。
- 映像对象持有 `mm` 和每个已映射页的 VA/PA。叶子映射成功后才进入清单。失败时先释放尚未映射的页，再逆序解映射已记录的叶子并按返回 PA 释放，最后销毁空 `mm`。清理只在根切离、完成 TLBI、取消发布且 IRQ 开启的线程上下文执行。无法确认旧 PA 或根状态时停机，避免释放仍可访问的页。

## 创建、切换与异常入口

- 先完成映像、任务身份、栈、调度上下文和首次 `pt_regs`，再按现有 task-list → runqueue 锁序发布。发布失败按逆序释放。提取现有内核线程构造中的通用分配、初始化和发布逻辑，保留旧内核线程的标志、架构资源和启动放行条件。用户任务固定 CPU0，要求 BSP 已完成调度与 IPI 就绪发布。父指针始终指向常驻的 BSP idle 任务，调用创建入口的线程可以独立退出。首版用户任务没有文件表或 FPU 分配。
- 任务持有映像和目录引用，`task->mm` 指向其映像的 `mm`。首个 `pt_regs` 位于该任务内核栈顶的固定位置。首次调度通过 EL1 入口完成已有的运行状态标记，再由共享恢复路径 `eret`。SVC 和 IRQ 保存的帧也在当前任务自己的栈上。让出时保留该栈及其帧，返回时只按 SVC 契约更新 x0。
- BSP 完成调度切换前保存原始内核 `TTBR0`。以 IRQ 屏蔽的架构切换路径安装下一任务的根，早于下一任务的 switch tail。旧根从实际安装状态获取，退出路径可能已经切回内核根。若下一根为用户根，先发布，再执行 `dsb ishst; msr ttbr0_el1; isb; tlbi vmalle1; dsb ish; isb`，之后才取消发布旧用户根。内核任务或 idle 安装保存的内核根。`TTBR1` 保持不变。同根切换可直接返回。根发布失败在切换不变量已被破坏时停机，正常单核切换最多同时保留两张用户根的发布记录。
- 用正常运行期 EL0 向量识别当前正式任务。先确认 CPU 和调度已就绪，再读取基于栈的 `current`，核对 `PF_PROCESS`、映像、根和保存的 EL0t 状态。已有 M4 探针优先由原运行器识别并进入原回调。常规入口仅在不存在活动探针时识别正式任务。EL0 IRQ 复用 GIC 的 IAR/EOI 和现有返回帧，GIC、串口及可达中断路径使用内核映射。BSP 在允许运行用户任务前显式清除 `CPACR_EL1.FPEN` 并执行 ISB。用户态 FP/SIMD 指令触发同步异常。正式任务的未支持同步异常以 `(uint64_t)-EFAULT` 退出，并记录实际 ESR 和 FAR（FAR 有效时）。内核异常继续走现有处理。
- 在用户任务切换和成功替换时清零 `TPIDR_EL0` 与 `TPIDRRO_EL0`。首版用户映像不依赖 TLS。寄存器帧和 EL1 切换帧如需新增字段，应保留已有汇编偏移并更新静态布局检查。

## 普通镜像接线

普通 AArch64 构建包含共享 `fs/elf_layout.c`、用户映像及任务入口、运行期根取消发布接口、AArch64 EL0 同步／IRQ 向量以及 IRQ 槽位解码和后端校验。将 GIC 和 PL011 的高地址别名用于普通构建，使 IRQ 与诊断路径在私有 `TTBR0` 下仍可访问设备。旧探针回调、注入点、嵌入 ELF 和自测发起代码继续由 `AARCH64_EL0_TEST` 控制。

## SVC 与事务边界

使用 SVC immediate 区分内部操作。`#0x4d40` 让出，返回 x0=0。`#0x4d41` 替换映像，x0 是目录索引。`#0x4d42` 退出，x0 是原始退出值。未知 SVC 返回 `-ENOSYS`。失败和让出均只改 x0。替换成功从新 ELF 入口以新栈和全新寄存器帧继续，旧 PC 不再返回。

替换时，在当前 EL1 异常帧下临时打开 IRQ，在未安装的新根上构造映像，期间不调度。旧根和旧任务状态保持可用。构造失败释放新对象，将错误写入旧帧 x0 后返回。构造完成后关闭 IRQ，在同一个提交区先发布并安装新根，完成 TLBI，再取消发布旧根并更新 `task->mm`、映像指针及返回帧。提交后的旧映像清理在 IRQ 已开启的 EL1 线程上下文完成，期间不调度。最终关 IRQ 并用新帧返回。提交区内不得有可恢复失败，且 IRQ 观察不到硬件根与任务元数据不一致。IRQ 分派路径只记账或置调度请求，不能在上述事务中调度。

退出时，先在 IRQ 屏蔽下切回内核根，完成 TLBI，取消发布旧根并清除任务对映像的引用。开启 IRQ，在旧任务自己的 EL1 栈上清理映像，随后走通用的自回收退出尾部。尾部记录原始状态、从任务表移除、标记 ZOMBIE 和 `PF_SELF_REAP`，永久切出。下一任务的 switch tail 释放旧线程上下文和内核栈。用户任务的退出入口与现有 kthread 退出检查各自验证调用者，共用已具备回收契约的尾部。

## 验收

沿用 `AARCH64_EL0_TEST=1 SMP=1` 的一次单核 QEMU 启动，新增 late case `aarch64_user_task_lifecycle`，独立于 M4.7 的 `aarch64_el0_task`。两个真实用户任务运行同 VA 的 ELF，各自写入不同数据与栈值，至少交替让出一次并验证 PC、寄存器、数据、栈及各自私有根。按 PID 记录真实用户任务切换和恢复。至少观察一次真实 EL0 CNTP IRQ 完成 GIC 分派后返回，核对中断前后 PID 和该次分派中的调度切换计数。

同一次启动中，用错误 ELF 和仅在自测构建启用的一次性分配失败验证回滚。注入必须发生在至少一张叶子成功映射后。两次失败都要核对旧映像可继续、旧私有根未替换且 4 KiB 计数恢复。随后成功替换为另一静态 ELF，核对 PID 不变、新入口和新栈生效、旧根撤销归属。按 PID 核对 guard 访问的 Data Abort、翻译错误类别及 FAR。用现有 switch tail 自测观察点在释放前记录各 PID 的原始退出值，以区分正常退出与 guard 终止。确认内核线程继续运行，最终用户页和线程资源均回到基线。对普通 AArch64 运行现有符号审计，并正向检查运行期 loader、spawn、根取消发布及两条低 EL 向量到正式入口的接线，同时检查探针符号和 ELF 数据排除。共用调度器运行受影响的宿主用例。
