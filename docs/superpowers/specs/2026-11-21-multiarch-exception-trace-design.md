# 多架构异常诊断与内核栈回溯设计

## 目标与方案

x86_64 和 AArch64 的内核致命异常使用 `kernel/core/trace.c` 输出相同格式的回溯。第一帧来自异常前的原生寄存器现场。调用链可读时显示符号和偏移，无法安全读取后续帧时仍输出第一帧。首期支持单段内核栈，覆盖 x86_64 被 IST 切换打断的任务栈、AArch64 高半区启动栈以及两架构的运行期任务栈。用户栈、跨栈续链、DWARF/ORC、自发 `kpanic()` 和全量寄存器输出留在范围之外。

沿用 `intr_event`、`arch_intr_dispatch()` 与现有架构后端。在后端选定致命分支后调用共享诊断。现有分派语义覆盖可恢复缺页、uaccess、信号、系统调用、IRQ 和异常返回。对应路径保持现有优先级及行为。共享分派在早期可达，继续只检查入参和事件类型。

候选做法包括让两个架构各自遍历并调用同一打印器，或统一遍历策略并由架构实现现场转换、栈归属和安全读取。本设计选择后者。两架构都使用递增地址方向的帧指针链，可以共享深度、边界、终止和符号规则。全量解码任意指令位置需要额外的展开元数据和工具链约束，当前只承诺有帧记录的内核调用链。[Arm AAPCS64 帧记录约定](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst#the-frame-pointer)

## 接口、输出与失败语义

- `kernel/include/core/trace.h` 声明 `trace_exception(const struct pt_regs *, enum trace_mode)`。模式为 `TRACE_FULL` 和 `TRACE_PC_ONLY`。入口接收已由架构异常入口建立的原生帧。中止/停机仍由调用者负责。
- `kernel/include/arch/unwind.h` 约定 `arch_unwind_init()`、`arch_unwind_read_frame()` 与返回地址查询地址转换。初始化提取 PC 与来源。只有 FULL 模式且确认属于内核时才解析 SP/FP、栈范围及帧对齐。读取钩子只负责从已校验的地址完整取出一对 `{next_fp, return_pc}`，失败时不提交记录。两个架构的实现放在各自的 `intr/` 下。公共层不会读取原生帧字段。
- 输出保留现有 `Kernel Stack Backtrace` 标题、`address:`、`function:` 和 `(no symbol)` 字段。先打印首帧，再尝试后续帧，总深度沿用 4。异常 PC 按原值查符号。返回地址按架构回退到调用指令范围（x86_64 减 1，AArch64 减 4，先检查下溢和 AArch64 指令对齐）。显示原始 PC，符号偏移按查询地址计算。无法归属的用户/未知来源只打印数值 PC。
- 栈范围用半开区间。访问前检查 SP 和 FP 在可信栈内、FP 不低于被打断的 SP、架构对齐且整个帧记录落在范围内，用减法检查长度以避免溢出。消费当前记录后，零链尾正常停止，其余下一 FP 必须严格增长且仍在原范围。非法或不可读的记录立即截断。后续 PC 的有效查询地址必须在已知的内核可执行范围内。保留已有的异常类型、硬件信息及现有 QEMU runner 依赖的 fatal 行。
- 共享输出直接复用 `arch_early_putc/puts`，使用简单的定宽十六进制和十进制输出。早期可达全链避免分配、常规 logger、锁、格式化库及 canary 读取。x86_64 在已经决定 fatal 后先屏蔽本地 IRQ，再用一次性原子操作认领先发者。胜者经无锁串口先打印原生异常主记录，再打印共享回溯，其他 CPU 或嵌套致命异常直接停机。AArch64 沿用 sync/SError 的 `first_fault` 仲裁。设备可用性沿用各架构已有致命输出阶段的约定。

## 架构现场与可读栈

### x86_64

从 `CS`、`RIP`、`RSP`、`RBP` 取来源和中断前现场。任务栈候选来自有效本 CPU 的 TSS `rsp0`，而不是从处理器此刻的 RSP 推导 `current`。读取 GS 数据前，读取当前 `IA32_GS_BASE` 并确认它指向 `percpu_data[]` 的完整对齐槽，用该槽的初始化/发布状态验证 TSS 已可用。TSS 指针只接受对应 CPU 的已知静态槽，BSP 用其实际硬件 TSS。发布门使用对应槽的 `online` acquire 读取。从已验证的 TSS 读取 `rsp0`，要求其为高半区、符合任务栈顶对齐，再按现有 `task_union` 布局排除 `task_t` 与栈底保留区。只在保存的 RSP 落在该区间时读取帧。BSP 已有静态 `init_task_union` 可直接作为早期候选，特殊栈、切换窗口与无法确认的范围退至 PC。

将 x86_64 原有 `backtrace(regs)` 调用迁移到统一的致命报告入口。#DF、NMI、#MC 使用 PC_ONLY。其余已判定终止的内核异常可尝试 FULL。把主记录的异常名、向量、错误码、RSP、RIP 用无锁输出写出，保留现有 #BP/#NMI runner 要求的字段与格式。#GP 可从保存现场输出附加寄存器，#PF 同时保留 `PF-KRN:`、原始 CR2 和原生错误码。终止路径移除持锁详细解码、并发任务链表遍历和通过任务指针、保存 SP 或 FP 裸读的转储。内核 #PF 的原有 uaccess 恢复只在验证当前任务栈归属后检查窗口。用户异常的既有结果保持，包括继续原本的信号/退出路径，以及原本就终止系统的异常只按用户来源输出 PC。

### AArch64

高半区 `el1_sync_entry` 保存 `PT_REGS_SIZE` 后直接传入其地址。对来自该入口且 `SPSR_EL1` 为 EL1h 的真实帧，以 `ELR_EL1/X29` 和 `(uintptr_t)regs + PT_REGS_SIZE` 初始化。EL1h 的 SP 由压栈关系恢复。保留 `pt_regs_t`、信号帧以及汇编返回布局。SError 所有来源首期只打印 PC。

先读取 TPIDR_EL1，按静态 `percpu_data[]` 首地址、总长度和槽步长验证并计算本 CPU 索引。正式 VBAR 安装前已设置该值。使用该索引的 `aarch64_boot_stack_top_addr()` 和高半区线性偏移检查本核唯一的启动栈槽。AP 的低身份映射启动栈、其他 CPU 的槽及无法验证 TPIDR 的现场只打印 PC。运行期使用同一个经过校验的索引，以每 CPU 一个自然对齐的原子整数发布已验证的当前任务栈基址，避免改动 `percpu_t` 布局。由 BSP/AP idle handoff 和 `arch_task_switch()` 在上下文验证后发布，任务栈固定布局推导可用下界与栈顶。共用构造器已采用的 `align_up(base + sizeof(task_t) + 256, 16)` 规则，发布者仅接受与该布局一致的已验证上下文。切栈前后若保存的 SP 与快照不一致，输出 PC 后结束。诊断端只访问静态槽、栈基址快照和经过检查的帧数据。BSP/AP 未接纳、紧急栈或其他未知栈均可完成 PC 输出。

EL1h fatal 在原有 `[aarch64-sync] FATAL` 完整输出后调用 FULL。SError 胜者同理在原有行后调用 PC_ONLY。两者依然通过各自停机点退出。

### 有界帧读取与嵌套异常

可信栈范围验证身份和几何边界，帧内存的实际可读性由架构窄作用域读取保证。每个架构用短汇编读取两个对齐机器字，标记两个载入指令与失败续点。传入的帧基址保留在原始第一参数寄存器，匹配器按载入标签分别检查基址和基址加 8。正常路径只在两次读取成功后提交输出。修复链和读桩在反汇编中验证无早期 canary 或常规日志依赖。

- x86_64 在 #PF C 落点快照 CR2 后、分派和 uaccess 之前，匹配 CPL0、两个私有载入 PC、#PF 错误码只允许 P 位变化以及 CR2 与尝试读取地址一致。命中只改保存的 RIP 并返回专用成功标志。异常桩仅对此标志直走原生恢复，避开 `ret_from_intr` 的返回工作和 IST 上的 current 访问。普通 #PF 仍走现有返回策略。汇编只在确认 `FUNC == do_page_fault` 后消费该专用状态值，其他 C 落点保持原返回分流。同步更新 `qemutests/intr_dispatch_audit.py` 的固定指令形状与负向 fixture，审计精确恢复边直接进入原生恢复，常规边仍可到 `ret_from_intr`，原单次 CR2 快照与分派约束继续生效。对可能引起 #GP 的非规范地址在读取前拒绝。
- AArch64 在 `aarch64_el1_sync()` 最前检查同级 EL1h data abort、有效 FAR（拒绝 FnV/S1PTW/CM/WnR）、翻译/权限/访问标志类 FSC 和私有载入 PC，且 FAR 等于尝试的地址。命中只改 ELR、通过向量桩原有 restore 返回读取失败路径。条件不匹配则按原顺序继续 uaccess 与同步异常分派。更新 AArch64 现有 dispatch audit，保留正常边，并核对新增早期修复分支直接返回原生恢复。标记、匹配和恢复都无需分配、调度或可变的全局恢复窗口。
- 两边只恢复可预期的地址翻译、访问权限类读取失败。重新发出的原生异常先于 fatal 诊断被精确修复。栈已无法保存异常现场、硬件致命中止等情况由现有紧急路径处置，超出这一读取保证。现有 x86_64 AP TSS 复用 BSP 的 IST 地址，且同一 IST 上的重入可能复写异常帧。首报仲裁发生在硬件压栈之后，回溯的保证以入口现场未被覆盖为前提。本期 IST 正例在单核验收，各核 IST 隔离由独立改动承担。

## 构建与符号契约

将 `core/trace.c` 显式加入 AArch64 内核源清单，两个架构各自链接自己的展开器和读取桩。Kernel-only 构建启用 `-fno-omit-frame-pointer`，按目标工具链需要显式保留叶函数帧指针。用 Release 反汇编核对，并运行已有栈预算审计。测试调用链使用禁止内联和尾调用的方式保证层级。生产尾调用、函数序言/尾声和手写汇编处允许缺帧。

继续使用现有两阶段链接。为两架构导出同名高半区可执行段边界供生成器和运行时使用，x86_64 分别覆盖 `.text` 与 `.ltext` 已有布局并识别空范围。AArch64 首期覆盖高半区 `.text`，低地址 `.boot.text` 的现场仍可输出原址。每段用半开区间。生成器按地址排序和确定性别名规则输出，运行时在同一可执行范围内找小于等于查询地址的最后一个符号。只在弱表存在且非空时读取，二分索引只使用 `[0, count)`，最后一项以段末为界。保留生成表目标架构的数据布局和两轮链接工作流。对两个最终 ELF 核对关键函数地址和表内容，确保常用异常及测试函数的解析结果与最终链接一致。

## 验收与实施顺序

1. 先交付通用符号范围、查询和双架构构建接入。宿主测试覆盖空表/单项/首末符号/空段/区间外地址/别名/返回地址边界，并审计两架构最终 ELF。
2. 实现安全帧读取、共享遍历和 x86_64 迁移。宿主测试用可计数的替身检查越界、溢出、反向/循环、零链尾、只打印 PC 和深度耗尽，另外验证精确 fault 恢复条件。复用现有 x86_64 #BP 变体证明多层回溯和 IST 使用保存的任务 RSP，独立测试变体区分坏 FP 截断与真实读取故障恢复。
3. 接入 AArch64 的启动与任务栈及 fatal 调用点。保留现有 `MODE=sync-fault` 证据，新增分别验证启动栈与运行期任务栈的正例，以及无可信栈、无可读帧时的 PC 退化路径。测试镜像独立，测试钩子不出现在普通 ELF。
4. 双架构的实际读取故障用例，在独立变体从仍可保存异常现场的内核栈直接调用生产 no-fault 读取钩子，使用可控相邻页区间，第一字在可读页末尾，第二字在已核实未映射的下一页。保留输出哨兵来验证第二次载入失败也不会提交半条记录。测试映射在架构允许的初始化/自测阶段创建，不能撤掉承载测试/异常现场的栈页。另用生产 trace 验证坏 FP 在读取前截断。双架构 QEMU 都核对第一帧与已保存 PC 一致、预期多层符号顺序正确、不可读帧只截断一次且未进入新的 fatal/调度路径。保留既有 fatal runner 的记录和唯一性规则。宿主用例用 `@os01-test` 元数据注册并运行 `make regen-test-catalog`。运行 `make test-host`、`make test-static`、`make test-harness`、x86_64 `SUITE=intr-x86` 和 AArch64 `MODE=sync-fault`、`MODE=serror`。分别运行 `make OS01_SYSTEST=1 test-syscall`、AArch64 `MODE=user-runtime` 及与改动相关的调度回归。syscall 与内核自测分开构建。
