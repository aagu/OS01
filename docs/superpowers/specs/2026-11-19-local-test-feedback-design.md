# OS01 首批测试简化：本地反馈优先

## 目标与取舍

让 `make test` 成为修改代码后可反复运行的本地检查：保留现有宿主回归，避免为了获得第一轮反馈而构建客体镜像、启动 QEMU 或跑完整框架回归。首批不改 PR 或夜间门禁，不重写 runner，不按用例数量裁剪覆盖。

- **推荐：组合现有快目标。** 增加一个顶层聚合目标，不复制用例注册、runner 或选择逻辑；适合先交付可用入口并测真实耗时。
- **暂缓：按 Git diff 自动选择测试。** 对小改动可能更快，但当前 catalog 不是完整的源码到场景依赖图；漏选会给出误导性的通过结果。
- **暂缓：在本地并行跑完整矩阵。** 仍须准备镜像和测试变体，也需要处理共享产物和独占套件，不能解决日常检查范围过大的问题。

## 首批行为

1. 顶层 `make test` 组合 `check-test-catalog`、`test-host`、`test-framework-contract` 和 `test-assertion-policy`，任一失败即返回非零。默认 profile 沿用现有 x86_64；不支持完整宿主回归的显式 profile 不得静默跳过。`make` 的默认构建目标不变。各子系统仍用已有定点入口，首批不引入新的 `CASE=` 语义。
2. 不把 `test-harness`、`test-static` 整包、QEMU 或镜像构建接进该目标。已有命令与 CI 日程保持不变。测试元数据和生成器仍是注册入口，不新增手写测试 ID 清单。
3. 先解决影响本地反复运行的宿主增量问题：已见 `devfs_vfs_production.d` 仍引用已迁移的 `kernel/arch/x86_64/fs/devfs.c`，而当前规则已指向 `kernel/fs/devfs.c`。对仍有有效编译规则、仅旧依赖文件引用消失主源的对象，验证其能重新编译，不要求全量清理；当前有效规则缺输入仍须报错，不改生产构建的错误语义。

## 计时与验收

- 已实测：`make check-test-catalog test-framework-contract test-assertion-policy` 通过，墙钟约 2.47 秒；`make test-host` 在约 3.02 秒时因上述旧依赖文件失败，不能作为成功基线。
- 实施时分别记录隔离的冷构建、无变更热跑、单文件修改后的墙钟时间，至少比较宿主编译和实际运行两部分。以热跑 15 秒以内为首轮目标，不把它做成机器相关的硬门禁；超出则先定位慢项，不静默删除测试。
- 验收 `make test` 的冷、热和源文件迁移场景；确认不会启动 QEMU 或生成客体镜像，保留 `test-host` 的覆盖与失败退出行为。更新构建指南，明确快速检查不能替代 syscall、内核 selftest 或架构专属验证。

## 宏桩：独立变更，不阻塞快入口

首个候选为 `OS01_TEST_FB_SCROLL`，它从 x86 启动路径调用 `printk` 性能采样，未找到自动化消费者。确认该手工诊断可以退役后，再单独移除探针、声明和调用点，验证正常引导与现有滚屏行为测试；若指标仍有使用者，保留诊断并另行设计隔离。首批不批量迁移 `OS01_HOST_TEST` 或 `OS01_SELFTEST`，也不引入生产镜像可开启的测试开关。
