# OS01 轻量测试框架方案

日期：2026-10-05

状态：评审修订稿；本次仅编写和评审方案，尚未实施。

目标：在现有构建与测试体系上形成稳定、准确、可扩展的测试框架。

## 1. 需求与约束

本方案采用已认可的方向：Make 管理构建和镜像，Python 标准库管理宿主进程与 QEMU，C 测试使用小型注册表和断言接口。不以 TDD/BDD 为开发流程要求。

- 不新增 pytest、Unity、cmocka、Ceedling、Twister、YAML 库或其他第三方测试运行依赖。
- 保留现有 profile、能力门控、受控 sub-make、镜像变体隔离及测试桶入口。
- 同时适用于 x86_64 和 AArch64；平台特有验收规则继续由对应套件实现。
- 保留既有测试价值，按套件迁移，不一次性重写所有用例。
- 优先保证失败传播与可复现性，再改善组织和执行效率。
- 运行环境首先覆盖当前 Linux 开发机与 CI；本阶段不承诺 Windows 宿主支持。

完成标准：故意制造的断言失败、挂起、崩溃、空选择及缺失完成记录均能阻断测试；成功结果有完整依据；新增普通测试不需要复制进程管理代码。

## 2. 现状与问题依据

主要入口位于 `mk/components/run.mk`，宿主构建位于 `hosttests/Makefile`，x86 通用 QEMU runner 为 `qemutests/run_test.py`，AArch64 各模式使用专用脚本。

本轮盘点的证据如下，后续实施时须在当时的 HEAD 上重新确认：

| 问题 | 依据 | 处理方向 |
| --- | --- | --- |
| 宿主断言失败可能退出 0 | `TEST_RESULTS()` 清零统计，部分 main 随后读取失败数；临时负向用例已复现 | 输出不修改最终状态，统一返回失败状态 |
| 框架回归测试未完整接入 | `test_gfx_runner.py` 的成功夹具遗漏后续 Tetris/终端检查；本轮执行 10 项、2 项失败 | 修复夹具，建立明确的框架测试入口 |
| 测试清单重复 | 宿主 `TEST_BINS` 中 stdio registry 重复 | 重复 ID/二进制检测，避免重复计数 |
| 覆盖含义不清晰 | 部分 basic 测试自建实现；内核 `pipe_basic` 是无操作成功 | 区分模型与生产实现；占位不能计为有效通过 |
| QEMU 公共管理分散 | 通用 runner 丢弃 stderr、删除临时串口日志、每次等待重新扫描旧输出 | 公共进程管理、持久读取游标、独立日志 |
| CPU 配置含义不同 | 通用 runner 默认 `QEMU_SMP=1`，运行入口使用 `SMP`，内核自测另用专有参数 | 显式传递并记录有效配置 |
| CI/文档与实际入口漂移 | CI 没有覆盖完整测试桶；文档有旧别名和旧数量 | 按执行层接入并同步说明 |

不会以宿主模型测试通过推断真实内核实现正确；也不会以镜像构建成功推断系统运行验收通过。

## 3. 开源项目参考与方案选择

### 3.1 参考依据

- **xv6**：函数表注册、子进程执行、父进程检查状态，支持单项、快速组、连续运行及空闲页检查。借鉴简单注册与退出码传播；不机械复制到依赖同一进程状态的 OS01 用例。见 [usertests.c](https://github.com/mit-pdos/xv6-riscv/blob/riscv/user/usertests.c)。
- **HelenOS**：用户态 tester 用名称、说明、safe 标志描述测试，批量执行安全测试；危险测试显式选择。见 [tester.c](https://github.com/HelenOS/helenos/blob/master/uspace/app/tester/tester.c) 和 [官方教程](https://www.helenos.org/wiki/Tutorial)。
- **SerenityOS**：宿主与目标测试分层，目标 runner 检查子进程状态，测试模式启动后自动执行、通过串口输出，并可在完成后关机。借鉴职责分工，沿用 OS01 自己的 Make 体系。见 [RunningTests.md](https://github.com/SerenityOS/serenity/blob/master/Documentation/RunningTests.md)。
- **blog_os（教学项目）**：串口结果、主动结束 QEMU、宿主退出码映射与超时保护。`isa-debug-exit` 为 x86 特有技术，本阶段不作为公共依赖。见 [Testing](https://os.phil-opp.com/testing/)。

这些项目使用的完整工具链各不相同，本方案仅采用适合 OS01 的机制。

### 3.2 选项与决定

| 选项 | 优点 | 成本 | 决定 |
| --- | --- | --- | --- |
| 仅修补现有脚本 | 初始改动最小 | 生命周期和结果判定继续重复，新增套件成本高 | 作为第一阶段 |
| 标准库公共运行层 + 原有套件适配 | 无额外依赖，能渐进收敛并保留架构验收 | 需维护少量公共代码与自身测试 | 最终采用 |
| 引入综合第三方框架 | 现成功能多 | 新依赖、构建适配和迁移成本 | 本阶段不采用 |

## 4. 架构与职责

```text
Make 测试桶：构建、变体、能力门控、传递实际路径和配置
  ├─ 宿主测试二进制：真实代码/模型测试、断言、退出状态
  ├─ 静态审计脚本：产物/源码契约、退出状态
  └─ QEMU 套件脚本：选择场景、发送输入、校验平台行为
       └─ 公共运行层：进程、输出、截止时间、清理、结果落盘

Guest 内：内核 selftest / systest 注册表 → 逐项结果 → 最终汇总
Host 侧：验证完整性 + 异常/退出状态 → 命令退出码 + 日志 + JSON
```

边界：

1. **Make 是构建规则的唯一来源**。Python 不重复实现 profile/镜像选择，也不隐式执行 clean。
2. **套件负责语义**。COW 输入握手、DTB、AP ack、预期 fatal、网络应答等规则留在套件；公共层不根据通用 PASS 字符串判成功。
3. **公共层负责执行可靠性**。只提供进程、输入输出、等待、清理、归档和通用结果数据。
4. **每层保留自己的注册来源**。宿主二进制由 `TEST_BINS` 提供；内核/systest 用例由各自 C 表提供；不再维护一份复制所有 C 用例的中心清单。

建议公共文件组织：

| 文件 | 职责 |
| --- | --- |
| `qemutests/harness/process.py` | 宿主命令与 QEMU 进程生命周期、增量输出、输入、截止时间 |
| `qemutests/harness/result.py` | 结果类型、通用协议验证、JSON 归档 |
| `qemutests/test_harness_process.py` | 使用标准库 unittest 和短命子进程验证运行层 |
| `qemutests/test_harness_result.py` | 日志夹具验证完整性、计数与异常判定 |

公共代码留在 Python 测试目录；C 宿主接口留在 `hosttests/include/`。若新增内核公开测试接口，源文件与头文件须遵守 `kernel/selftest/` ↔ `kernel/include/selftest/` 的目录对称规则。内核和用户态测试不共用宿主 stdio 头，不新增 UAPI。

## 5. 执行模型

### 5.1 宿主 C 测试

- 继续生成独立测试二进制，逐个执行；一个二进制异常不阻止其余独立二进制收集结果。
- 修复 `TEST_RESULTS()`：结果输出不清零最终失败状态。显式初始化负责重置；审计多次调用结果宏的现有用例，保留需要的分组累计语义。
- 统计分开表达 **binary / case / assertion**；断言数量不等于用例数量。
- 断言参数只求值一次，避免失败打印再次执行有副作用的表达式。
- runner 提供单项超时并保存完整 stdout/stderr；正常退出 0 才有资格通过，信号退出记为崩溃。
- 协议迁移前，旧测试以修复后的退出码为主要依据；已报告失败却退出 0 的矛盾必须失败。协议迁移后还校验用例完整性。
- 新增/重构生产实现测试应链接真实源码，仅替换硬件或环境边界；模型测试显式标注为模型，不把全部 mock 重写列为本阶段前置条件。

### 5.2 Guest 测试

- 内核 selftest 保持原有执行时机；最终完成必须包含启动自测及调度后任务自测，不能在第一份汇总时提前判通过。
- systest 保留现有主测试程序，先支持列举和按稳定 ID 选择，再逐项评估子进程隔离。
- 对验证 fork/exec/wait 本身或依赖共享状态的用例，不把被测机制作为所有测试的强制隔离前提。
- 普通 syscall、文件和内存行为按组共用一次 QEMU 启动；预期 panic、AP 故障和资源耗尽各用独立实例/镜像。
- 每次 guest 运行仍由宿主设置总超时。guest 内的计时或 alarm 不能替代宿主保护。
- `pipe_basic` 等未实现测试应移除注册或输出带理由的 SKIP，不能输出 PASS。

### 5.3 QEMU 与交互

- 调用使用 argv 列表，不使用 shell 拼接；显式接收 firmware/image/QEMU 路径、CPU 数、内存及套件超时。
- 使用 `time.monotonic()` 建立运行截止时间；每次等待使用剩余预算，不能在连续步骤中不断重置总超时。
- 日志增量读取，保留跨块的未完成行和 UTF-8 解码状态；交互检查从持久游标之后开始，禁止命中前一条命令的历史 PASS。
- 同时排空需要读取的输出通道，避免 pipe 填满死锁；输入 flush，并在进程退出/管道关闭时明确失败。
- stderr 单独保存。确认 QEMU 已启动，不将启动失败误报为 guest 超时。
- 完整结果到达后继续观察 **1 秒**，收集当前运行的尾部异常；随后由 runner 主动停止 QEMU，排空输出并 wait 回收，再做最终判定。此窗口仅检查已到达/窗口内异常，不保证检测无限延后的崩溃。
- 预期故障套件等待指定异常证据；不能因提前出现某个普通成功标记而结束。
- 清理先 terminate，最多等待 **5 秒**，再 kill 并 wait；Linux 下清理 runner 拥有的进程组，覆盖它启动的辅助进程。中断和异常路径同样执行清理。
- runner 自己发起的停止与 QEMU 非预期退出分开记录；没有完成证据的超时/退出永远不是成功。
- 本阶段默认串行执行。若当前 recipe 使用可写磁盘，避免与同镜像的另一个运行并发；未来并行须先实现私有镜像/overlay 和资源隔离。

## 6. 结果协议与成功条件

### 6.1 最小行协议 v1

本协议适用于已迁移的普通宿主 C、systest 和内核自测套件。静态审计、旧格式套件和预期 fatal 套件使用 §6.2 的证据适配规则，不强制 guest 输出本协议。仅将以下完整、行首对齐的记录视为协议；普通日志照常保存：

```text
[TEST] START v=1 suite=systest expected=2
[TEST] SELECT cow_fork required=1
[TEST] SELECT mmap_protection required=0
[TEST] BEGIN cow_fork
[TEST] PASS cow_fork
[TEST] BEGIN mmap_protection
[TEST] SKIP mmap_protection reason=unsupported_configuration
[TEST] END suite=systest total=2 passed=1 failed=0 skipped=1
```

约定：

- suite/case ID 使用 `[A-Za-z0-9_.-]+`；诊断文字另起普通日志行。
- START 在开始执行前给出实际选中用例数量，且每轮只出现一次；紧随其后的 SELECT 记录在首个 BEGIN 前声明完整选中集合及必跑属性。END 必须来自最终协调者，且每轮只出现一次。
- SELECT 从本轮实际使用的现有注册表及过滤规则生成，不维护另一份 host 用例目录。宿主 runner 从 `TEST_BINS` 解析选择；systest 的 `--list` 与执行选择共用同一 C 注册表；内核自测协调者在执行前声明本配置下各阶段的选中集合。
- 宿主保存请求的选择条件。指定 CASE 时，声明集合和实际执行集合必须都是该 CASE；quick/full 时声明集合必须满足对应注册过滤规则。SELECT 数量必须等于 expected，实际 BEGIN 和终结 ID 集合必须与 SELECT 完全相等。相同数量但不同 ID 仍失败。
- SELECT 的 `required` 只能是 0 或 1；0 仅来自注册表明确的平台可选项，不能因实际执行失败临时降级。宿主保存的显式 CASE 请求使该项必跑。
- BEGIN 后必须恰好有一个同 ID 的 PASS/FAIL/SKIP；FAIL/SKIP 必须有非空 reason。
- 所有选中 ID 唯一；重复 SELECT/BEGIN/终结、未声明 ID、未知终结、未结束用例、未知版本、格式损坏和不一致汇总均失败。
- `total = passed + failed + skipped = expected`，实际观察到的用例数量也必须一致。
- 用例不输出伪造的整体 END；多核/任务输出通过一个测试协调者串行发布完整记录，避免记录交错。
- 内核多个阶段的结果由最终协调者合并后发布 END；中间阶段保留现有诊断。

### 6.2 结果分类

| 状态 | 含义 | 命令结果 |
| --- | --- | --- |
| PASS | 有效完整结果，满足套件语义与退出条件 | 可通过 |
| FAIL | 断言/行为不满足、结果协议无效 | 非零 |
| ERROR | 启动/文件/执行环境错误，或非预期进程崩溃 | 非零 |
| TIMEOUT | 截止时间内没有完成预期执行 | 非零 |
| SKIP | 明确不适用，带理由并符合套件策略 | 根据策略汇总 |

对已迁移普通 C 套件，整体通过还须满足：

1. 至少一个有效用例 PASS；零选择、全跳过不能构成绿色运行。
2. 没有失败、非预期异常和未完成用例；预期异常只在专用故障套件的精确规则下成立。
3. 必跑用例没有 SKIP。默认选择的普通用例均为必跑；仅明确声明的平台可选项允许跳过。故障套件不得以跳过代替验收。
4. 宿主进程满足退出条件；QEMU 满足有效完成证据加退出/受控停止条件。

其他执行层通过显式适配器生成 binary/suite 级结果，不能编造 guest case 或 v1 完成记录：

- **静态审计**：实际启动并完成指定审计程序、退出 0 且满足原有产物/诊断契约，才生成一个 audit/suite PASS；启动失败、未执行审计和超时不通过。
- **旧格式普通套件**：原有解析器校验其正向完成证据、失败/异常证据及计数（原格式提供时），再生成 binary/suite 结果；空日志不能通过。保留已有否定规则，迁移时不以单个通用 PASS 替代完整判定。
- **预期 fatal/故障套件**：由 host 适配器根据专用证据生成 suite PASS。不能要求已经进入 fatal 的 guest 再发布 END；也不能把任意崩溃或超时当作预期成功。例如 sync-fault 必须保留 armed/fatal 顺序、唯一性、寄存器字段、禁止后续正常运行等规则，且观察证据后由 runner 停止仍存活的 QEMU；即使日志有 fatal，QEMU 自行退出也失败。
- 这些适配器至少完成一个真实 binary/suite 级检查；零选择、全跳过或未完成验收整体非零。平台不适用可记录 SKIP，但不能将其包装成 PASS。

直接调用 runner 的退出码统一为 0（通过）、1（测试未通过，包括 timeout）、2（配置/运行环境错误）；Ctrl-C 采用 130。上述数值不约束被测二进制自身的细分返回码，也不承诺 GNU Make 原样透传 recipe 返回码：Make/CI 必须保留通过与非通过，JSON 记录 runner/child 返回码、细分状态和中断原因。无法建立归档时在 stderr 输出明确错误并返回非零，不能因报告写入失败而通过。

负向测试中正常打印的 FAIL 字样不自动成为失败；只有结构化失败或套件定义的真实异常证据才影响结果。旧解析器迁移必须保留其已覆盖的异常规则并补对应回归夹具。

## 7. 选择、配置与归档

### 7.1 保持入口聚焦

- 继续使用 `test-host`、`test-static`、`test-qemu SUITE=...`、`test-kernel-selftest`、`test-aarch64 MODE=...`、`test-contract`。
- 增加一个 `test-harness` 入口，显式运行公共运行层、结果解析器与现有 runner 自测；采用标准库 unittest。不要全目录自动发现会构建或启动 QEMU 的任意脚本。
- 单项选择先在原生程序支持，例如 `systest --list`、`systest --case <id>` 和宿主 runner 的 binary 选择。Make 仅在已有桶实际具备能力时转发 CASE，不把现有 `test-m1-host CASE` 扩大为含义不清的通用选择器。
- quick/full 分组通过注册表中的简单标志实现；故障测试由独立 SUITE/MODE 选择。不引入通用测试 DSL、插件注册或新的配置文件格式。
- `SMP` 成为 Make 侧传递的明确输入；兼容 `QEMU_SMP` 等旧参数时，冲突应报错。内核自测现有专有设置在兼容期保留，并记录实际生效值。

### 7.2 每次运行的最小归档

```text
build/<profile>/logs/tests/<suite>/<UTC-time>-<unique-id>/
  stdout.log       # 宿主命令输出或 guest 串口输出
  stderr.log       # 宿主进程/QEMU 诊断
  result.json
```

目录使用标准库创建唯一名称，成功与失败日志都保留；生命周期由用户清理/profile clean 管理。首次接入不添加自动删除策略。

JSON schema v1 至少记录：run ID、git revision 与 dirty 状态、profile、suite、请求选择条件与声明/实际 ID 集合（普通 v1 套件）、实际 argv、CPU/内存、镜像/固件路径与 SHA-256（有这些输入时）、开始时间、耗时、runner/child 返回码、是否受控停止、最终状态、计数单位、各用例状态/理由、日志路径。工具版本按运行记录一次。无 guest 协议的旧脚本以 binary/suite 为计数单位，不能编造 case 数量。

报告文件采用同目录临时文件加原子替换；中断或内部异常也尽力写 ERROR/中断原因。输入镜像归档前后身份应一致；运行自身可能写 guest 磁盘时，区分输入哈希与运行后哈希。

## 8. 迁移阶段与验收

各阶段独立交付；本节是迁移路线，具体实施步骤在设计确认后单独编写。

| 阶段 | 修改范围 | 验收 |
| --- | --- | --- |
| A：可信度修复 | 宿主统计/退出码、重复清单、图形夹具、框架测试入口 | 故意失败二进制让 test-host 失败；框架回归通过；无重复执行；现有宿主回归通过 |
| B：公共执行层 | 新增两个公共模块；优先接入 x86 通用 runner 与内核自测执行路径 | 启动失败/超时/中断均有结果与日志；无残留进程；旧 PASS 不匹配新命令；完成后无需固定等待 75 秒 |
| C：完整结果与选择 | 宿主 C、systest、内核自测渐进输出 v1；增加单项选择；处理占位 | 选中/执行 ID 与计数一致；单项选择只执行目标；同数量错 ID、空选择/全跳过/截断/重复/晚到异常均失败；异步任务自测被计入 |
| D：双架构与 CI 收敛 | 逐个接入 AArch64/重复测试；统一归档；同步构建文档和 CI | 原有 DTB/AP/GIC/M1/M3/预期故障断言不减少；CI 失败上传日志；实际配置明确 |

兼容策略：未迁移套件使用显式旧格式适配器，仍保留其成功条件和异常检查；新协议缺失不能回退成“有任意 PASS 就成功”。一个套件切换到 v1 后取消其宽松旧格式回退，避免版本误配。

阶段 B 不要求立刻迁移所有 AArch64 脚本；阶段 D 每迁移一个套件，先以录制日志验证解析规则，再执行该套件真实 QEMU 验收。构建契约继续在独立 checkout/CI job 运行。

## 9. 验证矩阵

框架自身的负向验证是本方案必需内容；不规定功能开发必须先写测试。

| 输入/条件 | 预期结果 |
| --- | --- |
| 断言失败后打印结果 | 非零退出；输出不会抹掉失败状态 |
| 二进制崩溃、启动失败、挂起 | 分别 ERROR、ERROR、TIMEOUT；其余独立二进制仍可汇总 |
| START 后无 END、半行 END、数量不一致 | FAIL；不能由历史成功日志补全 |
| 重复 ID/END、全 SKIP、不存在的 CASE | FAIL 或配置 ERROR；整体非零 |
| 请求 CASE=A，声明或实际执行 B，数量均为 1 | FAIL；不能只验证 expected 数量 |
| SELECT 包含 A/B，但漏跑 B 或用 C 替换 B | FAIL；声明与实际 ID 集合必须相等 |
| 静态审计退出 0、旧格式完整成功、精确预期 fatal | 各适配器按自身契约生成 audit/binary/suite PASS，不强求 guest v1 END |
| 带普通 FAIL 文字的成功负向用例 | 按真实结构化结果判定，不误杀 |
| QEMU 连续大量输出/UTF-8 跨块/EOF | 不死锁、不丢行；退出后排空并重新判定 |
| 第二次命令等待与第一次 PASS 相同 | 只匹配游标之后的记录 |
| 汇总后观察窗口内发生真实 panic | FAIL；窗口外风险有明确边界 |
| 启动自测通过但任务自测卡住 | TIMEOUT/FAIL |
| 预期 AP no-ack 或 sync-fault | 精确证据成立才 PASS，普通 timeout 不算 PASS |
| sync-fault 打印 fatal 后 QEMU 自行退出 | FAIL；保持原有“必须由 runner 主动停止”的规则 |
| Ctrl-C 或清理期间异常 | 清理自有进程，保留日志，无假 PASS |
| runner 返回 1/2/130 后经 Make 执行 | Make/CI 非零；JSON 保留实际 runner/child 返回码，不要求 Make 数值相同 |

真实回归按阶段使用：

- `make test-harness`（拟新增）、`make test-host`、`make test-static`。
- `make test-qemu SUITE=phase-0`；`make OS01_SYSTEST=1 test-qemu SUITE=systest`。
- `make KERNEL_SELFTEST=1 test-kernel-selftest`，与 syscall 回归分开。
- 改动到的 inittab/network/gfx/repeat 套件及对应 AArch64 MODE。
- 涉及内核结构变化时仍执行项目要求的 `make clean`，不以本方案替代现有构建约束。

CPU 矩阵：PR 必跑 x86 冒烟和 syscall 的 1/2 核、内核自测 8 核，以及 AArch64 2 核运行冒烟（可先复用现有 MODE 的窄配置）；定时/手动跑更完整 1/2/4/8 核及 RAM/故障矩阵。先测量耗时再确定调度频率；不能因慢套件拆出 PR 而取消其运行入口。

## 10. 范围、风险与后续触发条件

本阶段不做通用调度平台、分布式执行、自动重试、HTML/JUnit 报告、QMP 集成、全量 mock 重写或强制更换 C 断言库。JSON 与现有 CI artifact 已能支撑追溯。

主要风险及控制：

- **协议迁移改变日志**：分套件切换，保存旧夹具，对应 CI 同步更新。
- **调度后自测遗漏**：最终协调者等待任务完成；单测覆盖“启动成功但任务卡住”。
- **强制子进程隔离掩盖问题**：按用例评估，保留完整 terminal/ash 与共享状态场景。
- **公共层膨胀**：平台诊断留在套件；新抽象须证明至少两个调用方有实际共同需求。
- **完成后立即停止减少晚到异常观察**：固定尾部观察窗口、完整排空与最后判定；需要生命周期压力的套件另设持续运行场景。

只有出现以下真实需求时再扩大能力：并行导致共享资源冲突时增加资源锁/私有镜像；CI 消费方需要时增加 JUnit 导出；控制虚拟硬件状态的场景需要时接入 QMP；C 断言维护成本持续超过收益时再比较小型第三方库。

## 11. 最终验收清单

- [ ] 故意失败不会被汇总为成功；所有执行层向 Make/CI 传播失败。
- [ ] 成功、失败、崩溃、超时、不适用与环境错误均有清晰记录。
- [ ] 选中测试确实执行，必跑项不被跳过，数量与注册来源一致。
- [ ] 普通日志与机器结果分开解析；旧日志不能满足新的交互检查。
- [ ] 测试停止、异常和中断后无 runner 拥有的残留进程。
- [ ] 每次运行保留实际配置、完整输出及机器可读结果。
- [ ] x86_64/AArch64 既有关键验收规则均保留。
- [ ] 新增普通用例只修改本层注册及测试代码；新增套件复用运行层。
- [ ] 不新增第三方测试依赖，现有 Make/profile/变体契约保持有效。
