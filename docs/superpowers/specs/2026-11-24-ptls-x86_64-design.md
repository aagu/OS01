# Craton/OS01 x86_64 PT_TLS 最小支持

每个 x86_64 用户进程只有一个执行线程。装载器为带 `PT_TLS` 的主程序建立一块进程私有的静态 TLS，在首条用户指令前设置 FS base。程序可用编译器生成的 local-exec 指令访问 `.tdata` 和 `.tbss`，也可用原始 `arch_prctl` 读取或更换 FS base。

## 0. 范围与取舍

用户提供的实测样本为 TinyGo 0.44.0 的 x86_64 静态 `ET_EXEC`。其 `PT_TLS` 的 `p_memsz=8`、`p_filesz=0`，唯一 TLS 符号 `current_task` 保存 TinyGo runtime 当前 goroutine 的指针。本期目标是让具备该最小需求的 TinyGo 类静态产物在 Craton x86_64 用户态运行。装载器提供 8 字节零初始化 TLS，runtime 可用 `ARCH_SET_FS` 切换 FS base，再用 `ARCH_GET_FS` 读回。

支持固定地址 ELF64 x86_64 `ET_EXEC` 和现有静态 PIE 白名单内的 `ET_DYN`。当前 x86_64 用户程序默认走 PIE，因此两个入口在本期共享 TLS 验证与实例化逻辑。由内核装载器初始化，复用 spawn 和 exec 的 staged 生命周期。仅让 crt0 初始化会把模板错误移到 exec 提交后，还会遗漏自带入口的程序。仅开放 `ARCH_SET_FS` 可服务自管 TLS 的运行时，但无法让带 `PT_TLS` 的程序在入口直接访问 local-exec 数据。依据：[user/Makefile:79](../../../user/Makefile#L79)、[kernel/arch/x86_64/sched/exec.c:665](../../../kernel/arch/x86_64/sched/exec.c#L665)。

本期明确不做用户线程、`clone`/`clone3` 或 `CLONE_SETTLS` 实现、pthread、动态链接与 DSO TLS、其他 TLS 访问模型或运行时 TLS 重定位（包括 TLSDESC、DTV、`__tls_get_addr`）、glibc 线程控制块、FS 相对栈保护 ABI、GS 操作、FSGSBASE 启用、TLS 地址随机化和 aarch64 TLS。保留 Linux `clone` 的既有 fork 兼容映射。产品 libc、crt0、BusyBox 和默认 linker scripts 维持现有代码生成与链接方式。本期验证由自带 `PT_TLS` 的测试夹具完成。aarch64 产品装载器继续拒绝 `PT_TLS`，本期仅记录该行为。依据：[kernel/syscall/compat/table_x86_64.c:43](../../../kernel/syscall/compat/table_x86_64.c#L43)、[kernel/arch/aarch64/memory/user_image.c:95](../../../kernel/arch/aarch64/memory/user_image.c#L95)、[kernel/arch/aarch64/memory/user_elf.c:47](../../../kernel/arch/aarch64/memory/user_elf.c#L47)、[libc/arch/x86_64/user-pie.ld:5](../../../libc/arch/x86_64/user-pie.ld#L5)、[libc/arch/x86_64/user.ld:5](../../../libc/arch/x86_64/user.ld#L5)。

## 2. PT_TLS 装载与地址布局

### 2.1 预校验

1. `elf_load` 使用现有 ELF 头和同一份 PHDR 快照。用 `vfs_node_live_size(node)` 检查 PHDR 表偏移与长度的加法和文件上界，再分配、读取 PHDR。通过现有映像校验及 TLS 校验后才取 PIE 偏移、分配映像叶。新增 TLS 校验落在 x86 私有 loader。PIE 校验移除 PT_TLS 的无条件拒绝，保留其余格式和动态标签、重定位规则。依据：[kernel/arch/x86_64/fs/elf.c:146](../../../kernel/arch/x86_64/fs/elf.c#L146)、[kernel/arch/x86_64/fs/elf.c:192](../../../kernel/arch/x86_64/fs/elf.c#L192)、[kernel/arch/x86_64/fs/elf_pie.c:117](../../../kernel/arch/x86_64/fs/elf_pie.c#L117)、[kernel/arch/x86_64/fs/elf_pie.c:326](../../../kernel/arch/x86_64/fs/elf_pie.c#L326)。
2. 无 PT_TLS 则跳过 TLS，输出 FS base 为 0。仅接受一个非空 PT_TLS。重复头、`p_memsz == 0`、`p_filesz > p_memsz`、非法对齐、地址溢出或超出映像窗口返回 `-ENOEXEC`。TLS 头的链接 VA 区间须位于 ET_EXEC 的 `[X86_USER_MIN_ADDR, X86_USER_HEAP_LIMIT)` 或 PIE 的 `[0, X86_USER_PIE_LINK_END)`，排他末端可等于上界。带 TLS 的 ET_EXEC 拒绝 PT_INTERP 或 PT_DYNAMIC。现有窗口定义见 [kernel/include/arch/x86_64/user_layout.h:18](../../../kernel/include/arch/x86_64/user_layout.h#L18) 和 [kernel/include/arch/x86_64/user_layout.h:35](../../../kernel/include/arch/x86_64/user_layout.h#L35)。
3. 将 `p_align` 的 0、1 均解释为 1，其余须为不大于 4096 的 2 的幂。非空文件模板要求 `p_offset + p_filesz` 无溢出且未越 EOF，`p_offset` 与 `p_vaddr` 模 `A` 同余，并由单个已校验的 PT_LOAD 的文件区间覆盖。以 `p_vaddr - load.p_vaddr` 换算出的文件偏移必须等于 `p_offset`。纯 `.tbss` 时允许 `p_filesz = 0`，不读其文件偏移，也无需 PT_LOAD 覆盖。文件支持部分以外的 TLS 地址可以与普通 BSS 重合，实例化时仍独立清零。
4. TLS 实例的**整个页取整跨度上限为 64 KiB**，包含前后 padding 和 TP 自指针。检查所有加法、取整及区间端点，无效或超限统一返回 `-ENOEXEC`。64 KiB、布局和单头约束是本期设计值。

### 2.2 Variant II 实例化

`B = X86_USER_STACK_END = 0x20600000`，是本期 TLS 私有映射起点。它在现有 ELF/堆和栈以外，低于随机 mmap 基址。设 `A` 为归一化对齐，`r = p_vaddr % A`，`D = align_up(p_memsz + r, A) - r`。取 `TP = B + align_up(D, max(A, 8))`，模板目的地址为 `TP - D`。例如 `A=64, r=16, p_memsz=17` 时 `D=48`，模板从 `B+16` 起，TP 在 `B+64`。这使模板首字节符合链接时余数，同时 TP 自然对齐并保留链接器计算的负位移。分配范围为 `[B, align_up(TP+8, 4096))`，在 `[TP, TP+8)` 写 64 位小端 TP 自指针，供 `mov %fs:0` 及取 TLS 地址使用。依据：[kernel/include/arch/x86_64/user_layout.h:18](../../../kernel/include/arch/x86_64/user_layout.h#L18)、[kernel/include/arch/x86_64/user_layout.h:28](../../../kernel/include/arch/x86_64/user_layout.h#L28)、[x86-64 psABI 的线程指针约定](https://gitlab.com/x86-psABIs/x86-64-ABI/-/blob/master/x86-64-ABI/low-level-sys-info.tex)、[LLD 的 Variant II 位移计算](https://github.com/llvm/llvm-project/blob/main/lld/ELF/InputSection.cpp)。

- 映射为普通匿名私有 VMA (`VMA_ANON | VMA_PROT_READ | VMA_PROT_WRITE`，无文件和共享 backing)，全部 4 KiB 叶起始即 user/RW/NX。先确认整个区间无重叠 VMA 和占用页（包括 PROT_NONE 与 2 MiB 叶），再通过内核物理直映清零整页和填充。用户可用既有 VM 操作修改或撤销这块映射，之后的 FS 访存由普通用户缺页及保护规则处理。无 TLS 映像不占用该地址。依据：[kernel/arch/x86_64/memory/mmap.c:42](../../../kernel/arch/x86_64/memory/mmap.c#L42)、[kernel/arch/x86_64/memory/mmap.c:475](../../../kernel/arch/x86_64/memory/mmap.c#L475)、[kernel/include/arch/x86_64/vma.h:32](../../../kernel/include/arch/x86_64/vma.h#L32)、[kernel/arch/x86_64/memory/vmm.c:297](../../../kernel/arch/x86_64/memory/vmm.c#L297)、[kernel/memory/vm_area.c:33](../../../kernel/memory/vm_area.c#L33)。
- 现有 PT_LOAD 完成拷贝和清零，PIE 完成原有重定位后，从目标 mm 中的 `bias + p_vaddr` 跨页拷贝恰好 `p_filesz` 字节。通过目标页表定位源和目的物理页，按两侧页边界分块，禁止按当前进程的用户指针解引用。PIE 白名单已允许的 `R_X86_64_RELATIVE` 对文件模板字节所做的修正因而进入实例。剩余 `p_memsz - p_filesz`、所有 padding 和页尾保持为零。短读沿原 PT_LOAD 错误路径返回 `-ENOEXEC`。缺失源叶或地址碰撞返回 `-ENOEXEC`，分配 VMA、叶或建页失败返回 `-ENOMEM`。依据：[kernel/arch/x86_64/fs/elf.c:306](../../../kernel/arch/x86_64/fs/elf.c#L306)、[kernel/arch/x86_64/fs/elf.c:331](../../../kernel/arch/x86_64/fs/elf.c#L331)、[kernel/arch/x86_64/fs/elf.c:344](../../../kernel/arch/x86_64/fs/elf.c#L344)。
- 新增 `uint64_t fs_base` 到 `x86_elf_image_t`，成功后交付 TP，`elf_load` 签名维持现状。TLS VMA 在最后一个可失败的装载操作后插入。插入前 TLS helper 独占临时 VMA 和已安装叶的回滚，映射每页失败后释放该页并撤回此前新装叶，TLS 目标区既有 PTE/VMA 及其字节保持原样，loader 输出保持原样。生产调用方只向新 mm 装载，失败时销毁新 mm 并回收其中间表。ET_EXEC 既有 PT_LOAD 分支仍可复用调用方传入的兼容叶并覆盖其内容，装载器回滚只撤回自己新装的 PT_LOAD 叶。成功后改由 mm 的普通 VMA 路径回收叶，PT_LOAD 回滚清单维持原边界。TLS 不参与 `start_code/end_code` 或 brk、auxv 计算。依据：[kernel/arch/x86_64/fs/elf.c:261](../../../kernel/arch/x86_64/fs/elf.c#L261)、[kernel/arch/x86_64/fs/elf.c:364](../../../kernel/arch/x86_64/fs/elf.c#L364)、[kernel/arch/x86_64/fs/elf.c:379](../../../kernel/arch/x86_64/fs/elf.c#L379)、[kernel/arch/x86_64/memory/vma.c:48](../../../kernel/arch/x86_64/memory/vma.c#L48)、[kernel/arch/x86_64/sched/exec.c:335](../../../kernel/arch/x86_64/sched/exec.c#L335)。

## 3. arch_prctl、切换与进程生命周期

### 3.1 原始 syscall 契约

新增原生 `SYS_arch_prctl = 79`，位于现有 `SYS_fsync = 78` 后，扩展分发表上界并注册到 x86 全量表已有的 `int64_t sys_misc_dispatch(syscall_ctx_t *ctx)`。Linux 标记的映像由兼容表把 158 映射到同一入口，沿用 `int64_t compat_linux_dispatch(syscall_ctx_t *ctx)` 的 1:1 重映射。两路均以 `args[0]` 为完整 64 位操作码，`args[1]` 为数值或指针，经 RAX 返回 0 或负 errno。依据：[kernel/include/uapi/syscall.h:105](../../../kernel/include/uapi/syscall.h#L105)、[kernel/syscall/dispatch.c:118](../../../kernel/syscall/dispatch.c#L118)、[kernel/arch/x86_64/syscall/sys_misc.c:17](../../../kernel/arch/x86_64/syscall/sys_misc.c#L17)、[kernel/syscall/compat/dispatch.c:22](../../../kernel/syscall/compat/dispatch.c#L22)、[kernel/syscall/compat/dispatch.c:48](../../../kernel/syscall/compat/dispatch.c#L48)、[Linux x86_64 syscall 表](https://github.com/torvalds/linux/blob/master/arch/x86/entry/syscalls/syscall_64.tbl)（宿主 Linux UAPI `/usr/include/asm/unistd_64.h:162` 也定义了 158）。

| 操作 | 行为 |
|---|---|
| `ARCH_SET_FS = 0x1002` | 接受含端点的 `[0, X86_USER_ADDR_LIMIT]`，上界 `0x00007FFFFFFFFFFF`。0 清空基址，允许尚未映射或未对齐的低半地址。其余值返回 `-EPERM`，不改变状态。成功时在关 IRQ 窗口将 FS 选择子装为 0，再写 IA32_FS_BASE，并同步当前任务保存值。 |
| `ARCH_GET_FS = 0x1003` | 读本任务 live MSR，用 `ssize_t copy_to_user_ft(void *dst, const void *src, size_t n)` 输出 8 字节至用户指针。完整写入返回 0，空/不可写/越界用户目标返回 `-EFAULT`，COW 准备分配失败原样返回 `-ENOMEM`。GET 不改 FS。 |
| 其他操作码 | `-EINVAL`，包括 GS 两个操作，以及仅低 32 位看起来有效的操作码。 |

数值与 Linux UAPI 一致，按 OS01 的用户地址上界与 uaccess 契约执行。测试使用现有 `int $0x80` 入口。TinyGo 样本用于确立 ELF 与 FS 的需求，现成二进制的调用指令、ABI 标记及其余 syscall 需求须独立验收。依据：[Linux x86 prctl UAPI](https://github.com/torvalds/linux/blob/master/arch/x86/include/uapi/asm/prctl.h)（宿主 `/usr/include/asm/prctl.h:5–8`）、[Linux SET/GET 实现](https://github.com/torvalds/linux/blob/master/arch/x86/kernel/process_64.c)、[kernel/include/arch/x86_64/user_layout.h:27](../../../kernel/include/arch/x86_64/user_layout.h#L27)、[kernel/include/memory/uaccess.h:45](../../../kernel/include/memory/uaccess.h#L45)、[kernel/include/memory/uaccess.h:59](../../../kernel/include/memory/uaccess.h#L59)。

### 3.2 FS 所有权

- 在 x86 `thread_t` 尾部新增 `uint64_t fs_base`（偏移 80，结构体 88 字节），保留既有字段和全部偏移。切出先读 live FS base 和选择子再覆盖硬件，切入先恢复选择子，再写 base。切换保持在既有 IRQ-disabled 区间，在发布 prev 离 CPU 前完成保存。内核任务、idle 初始 base 为 0，保留原 FS 选择子初始化。只触碰 FS，`GS` 继续是 per-CPU 状态。底层用既有 `uint64_t rdmsr(uint32_t msr)` / `void wrmsr(uint32_t msr, uint64_t value)`。依据：[kernel/include/arch/x86_64/context.h:20](../../../kernel/include/arch/x86_64/context.h#L20)、[kernel/include/arch/x86_64/context.h:106](../../../kernel/include/arch/x86_64/context.h#L106)、[kernel/include/arch/x86_64/msr.h:11](../../../kernel/include/arch/x86_64/msr.h#L11)、[kernel/include/arch/x86_64/msr.h:22](../../../kernel/include/arch/x86_64/msr.h#L22)、[kernel/arch/x86_64/cpu/switch.c:167](../../../kernel/arch/x86_64/cpu/switch.c#L167)、[kernel/arch/x86_64/cpu/switch.c:202](../../../kernel/arch/x86_64/cpu/switch.c#L202)。
- spawn 在入队前写入新任务选择子 0 和 `elf_img.fs_base`，首次切入加载，创建者的 MSR 不变。exec 在现有 mm/CR3 提交窗口同步安装选择子 0 和新 TP，无 TLS 则写 0。成功的 TLS→TLS exec 即使重用同一数值地址也得到新模板。失败的 exec 保留旧 mm、CR3、选择子、FS base、TLS 字节和用户入口。退役映像与退出进程由现有 mm/VMA 释放路径回收。依据：[kernel/arch/x86_64/sched/exec.c:607](../../../kernel/arch/x86_64/sched/exec.c#L607)、[kernel/arch/x86_64/sched/exec.c:790](../../../kernel/arch/x86_64/sched/exec.c#L790)、[kernel/arch/x86_64/sched/exit.c:114](../../../kernel/arch/x86_64/sched/exit.c#L114)。
- fork 继承调用者的 live 选择子和 FS base（包括手动设置的值），在子任务入队前完成快照。复制继承的是父进程当前字节和地址，私有 TLS VMA 走既有复制/COW，父子后续写入互不可见。无 TLS 时同样继承手工设置的 base。快照按同一次本地执行上下文读取，切换到子任务后才变更它的硬件状态。原有用户返回汇编帧只恢复 DS/ES，此期不加 FS/GS 字段。依据：[kernel/arch/x86_64/sched/fork.c:79](../../../kernel/arch/x86_64/sched/fork.c#L79)、[kernel/arch/x86_64/sched/fork.c:178](../../../kernel/arch/x86_64/sched/fork.c#L178)、[kernel/arch/x86_64/sched/fork.c:534](../../../kernel/arch/x86_64/sched/fork.c#L534)、[kernel/arch/x86_64/intr/entry.S:34](../../../kernel/arch/x86_64/intr/entry.S#L34)。

## 4. 验收与风险

先加测试并确认 RED 命中预期断言，再实现并跑同一测试至 GREEN。每个修复单独提交之前都跑顶层 `make OS01_SYSTEST=1 test-syscall`，不搭配 `KERNEL_SELFTEST=1`。用 `QEMU_SMP_MATRIX="1 2"` 复查单核切换及多核运行，另跑 `make test-host`、`make test-static`、`make PROFILE=x86_64-clang test-libc-api-audit` 和 `make test-qemu SUITE=phase-0`。验收契约与实际目标见 [AGENTS.md:15](../../../AGENTS.md#L15)、[mk/components/run.mk:1396](../../../mk/components/run.mk#L1396)、[mk/components/run.mk:1625](../../../mk/components/run.mk#L1625)。

| 风险 | 可证伪的验收 |
|---|---|
| 链接位移、页边界或 BSS 处理错误 | 宿主真实 loader 夹具覆盖非零余数、`p_align=0/1`、TinyGo 样本形状的纯 `.tbss`（8 字节全部为零，模板读取次数为 0）、目的和源跨页、64 KiB 边界、零填充及 TP 自指针。QEMU 执行含实际编译器 local-exec 访问的 ET_EXEC 和 PIE，核验变量值、取地址、写入和 FS:0。 |
| 文件边界或失败清理错误 | 重复/空/越界/未覆盖的模板、非法对齐、加法溢出、PIE 不支持的重定位应报 `-ENOEXEC`。注入短读、VMA 或物理页分配失败、首个 TLS 叶建页表分配失败，以及地址碰撞。另在宿主替身中注入后续映射失败以核对通用回滚。以上用例验证 TLS 目标区哨兵映射及其字节、进程旧 mm 和输出都保留，已安装叶只释放一次。 |
| TinyGo 类静态产物无法实际运行 | 同一个静态 ET_EXEC 从首条用户路径读取 8 字节零初始化的 `current_task`，随后 SET_FS 到一个自管用户块，GET_FS 校验新 TP，并用编译器生成的 local-exec 指令从新块读取和改写 `current_task`。恢复原 FS 后校验原块未受改写，探针正常退出。 |
| 运行态 FS 串进程或错误访问用户区 | 原生与 Linux 编号各走实际分派，检查 SET/GET、失败原子性、清零、内核半区及非 canonical 值、只读目标、跨页 COW GET 和未知操作。两个任务用不同 base 实际阻塞/唤醒，确认 `%fs` 读取和值均隔离。 |
| exec 提交点遗漏 FS 或 fork 错误重置模板 | 宿主 spawn 测试验证保存值先于入队，exec 测试记录新 mm/CR3 和 FS 提交次序与错误回滚。QEMU 验证已有父进程写入由子继承，fork 后分别写入仍隔离，TLS→TLS 恢复模板，TLS→无 TLS 清零，失败 exec 保留旧 TLS 和手动 FS。 |
| 兼容性回归 | 现有无 TLS 的 ET_EXEC/PIE、ASLR、信号返回、fork/exec/waitpid、x86 引导和 libc API 审计通过。aarch64 的 syscall subset 和 PT_TLS 拒绝不变。 |
