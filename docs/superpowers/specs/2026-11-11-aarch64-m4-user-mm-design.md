# AArch64 M4 用户页表与 `mm` 生命周期设计

## 目标

为 AArch64 正式用户地址空间建立 `mm` 所有权。内核可以在运行期创建一个独立的低地址页表根，通过 M3 的 `arch_vmm_*` 接口查询、映射、改权限和解映射 4 KiB 页，再安全回收根及中间页表。验收用例复用已有 EL0 入口，实际访问这张页表，验证权限变化和 TLB 失效。

首个交付限制在单核 BSP、ASID 0 和普通 RAM 的 4 KiB 页。可修改的用户根必须已经切离 `TTBR0`，查询允许在根安装期间进行。正式任务切换、活动根写入、VMA 和缺页处理、`fork`/COW、`PROT_NONE`、设备映射和用户大页属于后续交付。普通镜像的用户态开关继续由现有启动契约管理。

## 现状与接口选择

- `mm_t.pgdir` 当前保存根的物理地址，`arch_vmm_*` 和 AArch64 页表原语接收直映虚拟指针。保留两者的表示，在内存管理边界显式转换。写入 `TTBR0_EL1` 时使用物理地址，`TTBR1_EL1` 保持内核映射。
- M3 的四个 4 KiB 入口当前只接受 `kernel_map`。本设计扩展同一组接口，通过显式登记识别由 `mm` 拥有的用户根，再调用已有的 4 KiB 页表原语。归属记录随 `mm` 创建和销毁，查询、更新和删除都依赖它。
- 另一种方案是为用户页表提供一套独立的 map/query/update/unmap 接口，入口可直接接收 `mm_t *`。这会让后续 ELF 和 VMA 维护两套返回值和权限契约。本设计只为 `mm` 新增生命周期入口，沿用 M3 的 `VM_*` 表示和四个操作。
- 现有 M3 published-root 表跟踪可安装或曾经安装的根，当前容量为 8。用户根归属使用独立的动态链表，每个 `mm` 对应一条记录，无固定槽位上限。创建未安装的 `mm` 不占用安装表槽。归属记录分配失败返回 `-ENOMEM`，并回收已分配的 `mm` 和根页。现有 `kernel_map` 与 M4.1–M4.7 探针维持各自的登记与使用方式。

## `mm` 生命周期和所有权

将 `mm_t *mm_alloc(void)` 从 `kernel/memory/vma.c` 移到双架构共编译的 `kernel/memory/mm.c`，声明移至 `kernel/include/memory/mm.h`。保留零初始化、空 VMA 链表、`mmap_base` 和锁初始化的原有语义。AArch64 生命周期接口放在 `kernel/arch/aarch64/memory/user_mm.c` 与 `kernel/include/arch/aarch64/user_mm.h`。接口签名如下。

```c
int aarch64_user_mm_create(mm_t **out);
int aarch64_user_mm_destroy(mm_t *mm);
```

1. **创建。** `out == NULL` 返回 `-EINVAL`。有效的 `out` 在入口清零。通过运行期检查后调用 `mm_alloc()`，分配并清零根页，登记归属并设置 `pgdir`，最后写入 `*out` 并返回 0。分配失败返回 `-ENOMEM`，释放已分配对象。
2. **使用。** `mm` 独占根及所有中间表页。数据页由映射调用方持有。映射成功建立页表引用，失败时调用方仍可释放尚未映射的页。更新权限沿用相同 PA，成功解映射后通过返回的旧 PA 交还调用方释放。M3 操作本身不释放数据页。
3. **安装。** 验收直接复用 `aarch64_el0_run_kthread()`，由运行器先发布根，再以 ASID 0 安装到 BSP 的 `TTBR0`，并在返回前恢复原根、完成本地 TLB 失效和取消发布。首版的生命周期接口只负责创建和销毁。归属登记在切换前后都有效。用户根的写入口和销毁入口同时检查发布登记及硬件 `TTBR0` 根地址。
4. **销毁。** 调用者先确保没有在途的页表操作，切离根并完成失效，再解映射所有叶子和释放数据页。`NULL`、`init_mm` 和无归属记录的 `mm` 返回 `-EINVAL`。销毁先只读扫描整棵树，确认没有任何叶子映射，包括意外出现的块映射或保留 PA 的无效叶子。已安装、仍已发布或含叶子的根返回 `-EBUSY`，树、归属和 `mm` 均完整保留。扫描通过后才撤销归属，第二遍释放全部中间表及根页，最后释放 `mm` 并返回 0。建表失败留下的空表也由第二遍回收。

首版由一个 BSP 内核上下文持有 `mm`，持有者串行化映射操作、安装和销毁。登记锁采用 IRQ 安全方式，覆盖归属的查找、加入和移除，在调用 M3 页表操作或释放页前放开。调用方在整个操作期间保持 `mm` 存活。

## 运行期门控与检查顺序

在 `vmm_gate.c` 和对应头文件提供可返回错误的 `int aarch64_user_mm_runtime_check(void)`。SMP bring-up 尚未开始返回 `-EAGAIN`。进入 bring-up 后，DTB CPU 数不是 1 或调用 CPU 不是 BSP 返回 `-EOPNOTSUPP`，IPI 就绪计数不是 1 返回 `-EAGAIN`。创建、销毁和用户根的四个 M3 入口均使用该检查。用户根路径在 `vmm_gate_check()` 前调用它，未就绪时可正常返回，已获准的实际页表操作继续经过 M3 门控。内核根保留原来的门控和违规处理。直接链接 `vmm_backend.c` 的宿主测试通过现有 stub 层提供新依赖，CPU 和 IPI 状态留在 `vmm_gate.c`。

用户根入口先确认根归属，再检查运行期条件。对 map/update/unmap，随后检查发布状态和 `TTBR0`，任一命中即返回 `-EBUSY`。这条拒绝路径允许在 DAIF.I 已屏蔽的 SVC 回调中执行，不进入页表原语，也不触发 `vmm_debug_assert_irqs_enabled()`。通过检查并继续尝试修改时，仍要求调用者在本地 IRQ 已开启的线程上下文中执行。query 可在根安装期间读取，创建和实际销毁在 IRQ 已开启的线程上下文执行。

## 页表操作契约

| 操作 | 用户根首版行为 |
| --- | --- |
| `arch_vmm_map_4k_new` | 仅接收空槽、对齐的用户 VA 和有效的普通 RAM 页。成功建立映射，重复映射返回 `-EEXIST`。 |
| `arch_vmm_query_4k` | 返回 PA 和语义权限。未映射返回 `-ENOENT`，不分配页表。 |
| `arch_vmm_update_4k` | 参数格式有效时，先查叶子。无映射返回 `-ENOENT`。已有映射但传入 PA 与旧 PA 不同，返回 `-EINVAL` 并保留原叶子。PA 相同才更新权限，成功返回旧 PA 和权限。 |
| `arch_vmm_unmap_4k` | 清除叶子并返回旧 PA 和权限。重复解映射返回 `-ENOENT`。允许将空的中间表留给销毁入口回收。 |

四个入口均校验用户 VA 位于 `[AARCH64_USER_MIN, AARCH64_USER_LIMIT)` 且按 4 KiB 对齐。map/update 先检查 PA 的对齐、物理地址范围和权限掩码。map 在建表前检查 PA 属于已分配的 4 KiB 普通页，update 在确认叶子存在且 PA 相同后做同样的检查。未知根、越界、无效权限和不受支持的参数返回 `-EINVAL`。失败时保留已有叶子和调用方所有权，输出参数只在成功时写入。已有内核根分支和 2 MiB API 的行为保持原契约。

用户根只接受以下三个权限掩码。M3 用 `VM_NO_EXEC` 表示禁止执行，裸 `VM_USER_RW` 会请求 RWX，用户根返回 `-EINVAL`。所有用户映射禁止 EL1 执行。

| EL0 权限 | `vm_flags` |
| --- | --- |
| RW/NX | `VM_USER_RW \| VM_NO_EXEC` |
| RO/NX | `VM_USER_RO \| VM_NO_EXEC` |
| RO/X | `VM_USER_RO` |

## TLB 与后续接入边界

首版在每次安装和切离用户根时执行现有的 ASID 0 本地全失效与完成屏障。切离完成后才允许改表或释放数据页。因此同一根再次安装时，先前缓存的 RW 或存在翻译无法继续生效。归属登记不能作为 TLB 已失效的凭据。

接入正式调度和 VMA 时，需要增加安装在 CPU 上的根与 `mm` 生命周期之间的同步。届时活动根降权和解映射必须在返回或释放旧页前完成失效。需要改变 PA、内存类型或有效性的替换沿用 M3 的 break-before-make 协议。多核用户地址空间还需要明确远端驻留与 shootdown 的范围。首版在后台修改已切离的根，不依赖这些后续协议。

## 验收

在现有 AArch64 自测镜像加一个 late case，单次 `SMP=1` QEMU 启动即可验收。以 M4.7 已有的高地址内核栈和 EL0 返回路径运行短探针。探针代码、用户栈和测试数据映射到同一个 `mm` 根，全部经由 M3 入口。代码页填充后完成已有的指令缓存同步，再以 RO/X 安装。整个用例重复进入同一张页表，清理时也解映射探针代码和栈。

1. 创建私有 `mm`，分配一页并映射为用户 RW/NX。查询核对 PA 和权限。第一次进入 EL0，读取并写入已知值，使翻译进入 TLB。
2. 切离并恢复启动根。将同一 VA、同一 PA 降为 RO/NX，再进入 EL0。验证旧数据可读，写入发生预期的 EL0 权限异常，原数据不变。
3. 再次切离后解映射，核对返回的 PA 和 `-ENOENT` 查询结果。重新进入 EL0，验证访问该 VA 触发翻译异常。检查内核页表恢复后再释放数据页和销毁 `mm`。
4. 在第一次进入 EL0 的 SVC 回调中，以有效参数调用 map/update/unmap，确认三者在 IRQ 屏蔽且根已安装、已发布时均返回 `-EBUSY`。在根切离后的线程上下文中确认重复映射返回 `-EEXIST`，内核 VA、裸 `VM_USER_RW`、未分配 PA 和不同 PA 的权限更新返回 `-EINVAL`，更新空槽返回 `-ENOENT`。确认仍有叶子的 `mm` 销毁返回 `-EBUSY`，之后现有映射仍可查询、解映射并正常销毁。正常与失败清理结束后，PMM 的 4 KiB 已分配页数回到基线。串口使用一条自测 PASS 记录及已有的 suite END，无需新增 runner。
