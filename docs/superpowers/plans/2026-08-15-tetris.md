# Tetris 游戏实现计划（tetris-dev worktree）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 OS01 上实现可玩的俄罗斯方块：用户态 `user/tetris.c`（fb 渲染 + `/dev/keyboard` 扫描码输入 + Linux alt screen 协议），完整 TDD 流程，**每个 Task 测试回归通过才推进下一步**。

**Architecture:** 四层改造，全部在 tetris-dev worktree（`~/OS01-tetris`）：
1. **kernel keyboard poll** — `/dev/keyboard` 从非阻塞 + 无 poll 变为可阻塞/poll（游戏输入基础）
2. **tty termios 诚实化** — TCSETS 真存储、默认 raw、tty_read 尊重 ICANON/ECHO
3. **terminal.elf alt screen 双缓冲** — `\e[?1049h/l` 协议，游戏退出终端自动恢复
4. **user/tetris.c** — 游戏逻辑（纯 C 可 host 测）+ fb 渲染 + 扫描码解析

**Tech Stack:** C（clang `-target x86_64-unknown-none`）、host 单测（`test/cases/` + test_framework）、QEMU 集成（`tests/run_test.py` + `user/systest.c`）

- **commit 风格**：theme-based 小 commit、语义前缀（`feat(driver)`/`fix(tty)`/`feat(terminal)`/`feat(applets)`）、remove debug artifacts。
- **QEMU 实证**：每 Task 完成 QEMU 实跑验证（「通了再报进展」；未验证结论必须标注）。

### Task 1: keyboard poll — `feat(driver): keyboard poll support`（~31 行）

**Files:**
- Modify: `kernel/driver/keyboard.c`（scancode wait queue + `keyboard_poll_dev` + IRQ 唤醒）
- Modify: `kernel/kernel/main.c`（`keyboard_ops` 挂 `.poll`）

**现状（已核实）：** `keyboard_devfs_read` 纯非阻塞（ring 空返回 0）；`keyboard_ops` 仅 `.read`；devfs_poll 无回调时默认 always-ready（`POLLIN|POLLRDNORM|POLLOUT|POLLWRNORM`）→ `poll(/dev/keyboard)` 现在立即返回"可读"，等于空转。

**Interfaces（参照 tty.c 的 read_wait/read_poll 双队列模式）：**
```c
// keyboard.c 新增
static list_t scancode_wait;        // 阻塞读等待队列（本 Task 用 poll 则挂 read_poll 风格）
static spinlock_t scancode_wait_lock;
uint32_t keyboard_poll_dev(void *priv, poll_table_t *pt);  // ring 非空→POLLIN|POLLRDNORM；否则 poll_wait
```
- IRQ 路径 `keyboard_handler` push ring 后唤醒（参照 `tty_wake_waiters`：双队列 + `this_cpu()->need_resched = 1`）
- `main.c`：`keyboard_ops = { .read = keyboard_devfs_read, .poll = keyboard_poll_dev }`

**Steps:**
- [ ] **RED**: `user/systest.c` 增加 poll case——`open("/dev/keyboard")` + `poll(100ms)` 期望**超时返回 0**（无按键时不应 always-ready）。当前代码立即返回可读 → 断言失败（RED 确认，失败原因 = 功能缺失）
- [ ] **GREEN**: keyboard.c 实现 wait queue + `keyboard_poll_dev`（ring 空 → poll_wait，非空 → POLLIN）；main.c 挂 `.poll`
- [ ] **回归**: systest 全量（126 + 新增 case）+ `make -C test run`（host 9 套）
- [ ] QEMU 实证：`make run` 启动，shell 里手动验证 `poll(/dev/keyboard)` 阻塞行为
- [ ] commit: `feat(driver): keyboard poll support for /dev/keyboard`

### Task 2: tty termios 诚实化 — `fix(tty): make termios honest`（~60 行）

**Files:**
- Modify: `kernel/include/kernel/tty.h`（`tty_t` 加 `struct termios term`）
- Modify: `kernel/tty/tty.c`（ioctl 真存储 + tty_read ICANON/ECHO 分支）

**现状（已核实）：** `TCGETS` 硬编码谎报 `ICANON|ECHO|ISIG`；`TCSETS/TCSETSW` 是 `return 0` no-op；`tty_read` 实际 raw 搬运（行编辑靠用户态 busybox ash FEATURE_EDITING）。

**Interfaces:**
- `tty_alloc` 初始化 `term`：`c_lflag=0`（**raw 默认**）、`c_iflag=ICRNL`、`c_oflag=OPOST|ONLCR`、`c_cc[VMIN]=1`、`c_cc[VTIME]=0`
- `TCGETS` → `memcpy(arg, &tty->term)`；`TCSETS/TCSETSW` → `memcpy(&tty->term, arg)`
- `tty_read`：`c_lflag & ICANON` → **攒行等 `\n` 才返回** + `ECHO` 回显（每字符经 `echo_char`）；否则现 raw 路径

**明确不做（TODO 留档）：** ISIG/pgrp 信号（terminal.elf 用户态已处理 ^C→SIGINT）、OPOST/ONLCR 输出转换（物理 tty 输出无消费者）。

**Steps:**
- [ ] **RED**: systest 增加 termios case——① `TCGETS(/dev/tty)` 断言 `c_lflag == 0`（raw 默认，当前谎报 ICANON → 失败）；② `TCSETS` 设 `c_lflag=ICANON` 后 `TCGETS` 断言一致（当前 no-op → 不一致失败）；③ canonical 攒行行为（写入 3 字符 + `\n` 前 read 阻塞——QEMU 下难以自动测，host 单测覆盖）
- [ ] **RED (host)**: `test/cases/test_tty_termios.c` — 用 mock 编译 tty.c，测 `tty_alloc` 默认值 + ioctl 存取往返 + `tty_read` canonical/raw 分支（**TDD 核心：host 侧覆盖攒行逻辑**）
- [ ] **GREEN**: tty.h 结构体 + tty.c 实现
- [ ] **`make clean && make`**（结构体变更！）
- [ ] **回归**: host 单测 + systest 全量 + QEMU 实跑 terminal/ash 正常（回归关键：默认 raw 行为不变）
- [ ] commit: `fix(tty): make termios honest (store TCSETS, raw default, ICANON/ECHO)`

### Task 3: terminal alt screen — `feat(terminal): alt screen double buffer`（~80 行）

**Files:**
- Modify: `user/terminal.c`（抽 `terminal_core.c`：VT100 状态机 + 双缓冲模型，host 可测）
- Add: `user/terminal_core.c` / `user/terminal_core.h`（纯逻辑，无 fb/OS 依赖）

**现状（已核实）：** `put_glyph` 直接写 fb mmap（无离屏缓冲）；VT100 解析器 3 状态（`S_NORMAL/S_ESC/S_CSI_PARAM`），CSI 仅支持 `A/B/C/D/K/J/H/?25h/?25l`——**无 `?1049h/l`**。

**Interfaces:**
```c
// terminal_core.h
typedef struct { uint8_t glyph; uint8_t attr; } cell_t;
typedef struct {
    cell_t main_buf[25][80];   // 主缓冲（offscreen）
    cell_t alt_buf[25][80];    // alt 缓冲
    int    cursor_row, cursor_col;
    bool   alt_active;
} term_core_t;
void term_core_init(term_core_t *t);
void term_core_input(term_core_t *t, uint8_t b);        // 状态机喂字节
bool term_core_flush(term_core_t *t, void *fb, int stride); // 渲染到 fb（仅变化区）
```
- `?1049h`：保存主缓冲内容（实际是 memcpy 到 alt？协议语义：进入 alt 前主缓冲保持，`?1049l` 时**主缓冲原样画回**）→ 简化：`alt_active=true` + 清屏；`?1049l` → `alt_active=false` + 全量 flush 主缓冲
- terminal.elf 主循环改为：读 tty/pty → `term_core_input` → `term_core_flush`（每帧或脏时）

**Steps:**
- [ ] **RED (host)**: `test/cases/test_terminal_core.c` — ① 普通字符写入 main_buf；② `?1049h` 后写入进 alt_buf；③ `?1049l` 恢复 main_buf 内容；④ 光标移动/清屏序列仍工作
- [ ] **GREEN**: terminal_core.c 状态机 + 双缓冲（从现有 terminal.c 解析逻辑提取重构，行为不变）
- [ ] terminal.elf 接入 core（fb 渲染走 flush）
- [ ] **回归**: host 单测 + `make run` QEMU 实证——`printf '\e[?1049h'` 画东西后 `\e[?1049l` 终端内容完整恢复
- [ ] commit: `feat(terminal): alt screen double buffer (?1049h/l)`
