# AArch64 RP1 Interrupt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 让 RPi 5 的 RP1 UART0 通过可复用的中断服务向控制台 TTY 提供 RX，并保留启动轮询回退。

**Architecture:** UEFI 提供 RP1 BAR0 的可信长度，Stage 3 准备 RP1、MIP 和 PCIe MMIO 资源。BCM2712 MIP 分配上游 SPI，RP1 层拥有子源和 MSI-X 表项，控制台在排针 UART 上调用 RP1 注册接口。相同向量先通过 RP1 TEST 完成递送探测，再参与设备输入。

**Tech Stack:** freestanding C11、UEFI PCI I/O、FDT、BCM2712 PCIe/MIP、GICv2、RP1 MSI-X、PL011、OS01 hosttests 与 QEMU。

**Spec:** [AArch64 BCM2712 MIP 与 RP1 中断设计](../specs/2026-11-28-aarch64-rp1-irq-design.md)

## Global Constraints

- 仅在显式 RPi 5 `rp1-header` 路径获取 RP1 C0 `1de4:0001`、revision 2 的 BAR0 证据。v3 wire 长度 200，v4 记录追加在偏移 200。v3 兼容及汇编偏移保留。UEFI 数据使用固定宽度类型。
- RP1 源 0–60。USBHOST0/1 源 30–39 为 edge，其余 level-high。MSI 数据为 `offset + slot`，GIC INTID 为 `32 + base_spi + offset + slot`。64 位 MSI 消息地址与 CPU MMIO PA 各自保存。
- Stage 3 完成 Device-nGnRnE MMIO 预映射。保持固件 endpoint BAR、出站窗、现有 xHCI DMA 入站窗及 UART 固件配置。现有 x86 PCI MSI-X、QEMU GICv2m、直接 GIC SPI 和自测路径沿用现有行为。
- 启动 BSP、本地 IRQ 屏蔽下进行事务。真实 RP1 TEST 探测上限 10 ms。回滚后无法确认静默的资源留在隔离状态。控制台回退用 100 Hz BSP 轮询。生产日志用 `log_info`／`log_warn`。
- 测试依据仓库 `@os01-test` 元数据和现有链接模式注册。每批新增用例从根目录运行 `make PROFILE=x86_64-clang regen-test-catalog check-test-catalog`，提交生成物。每个任务按下表在 `hosttests/mk` 增加链接组，在 `mk/components/run.mk` 的 `host_case_group` 接线 `test-aarch64-rp1-irq-host CASE=...`，该入口独立于生成式测试注册。宿主回归命令使用 `PROFILE=x86_64-clang`，板镜像和 aarch64 QEMU 命令使用 `PROFILE=aarch64-clang`。

## Review Focus

- 老版 handoff 紧贴早期映射上界、v4 截断、UEFI BAR0 属性缺失时，延用 v3 启动与轮询，见任务 1 的边界用例。
- DTB 中 IRQ 支路无效且 xHCI 合法，以及 IRQ 合法而无 xHCI 描述，两条准备路径独立，见任务 2。
- RC 通用入站窗读回正确但 PCI 消息没到 GIC，以及内部 MSI 译码截获消息，无 IRQ 模式提交，见任务 3、4。
- 第二个 RP1 源注册失败且留下 PBA，已工作的第一个源继续递送，见任务 4。
- Arming 时的单字节及突发输入、UART mask 写入读回失败、post-arm USB 根盘读取，见任务 5、6。

### Task 1 — 固件 BAR0 证据与 v3/v4 ABI

**Files:** `kernel/include/core/bootinfo.h`、`kernel/core/main.c`、`kernel/arch/aarch64/boot/{early_mmu,main}.c`、`boot/uefi/main.c`、`boot/uefi/arch/aarch64/{boot,rp1_pci}.c`、`boot/uefi/arch/aarch64/rp1_pci.h`、`boot/uefi/Makefile`、`mk/components/uefi.mk`、`kernel/include/arch/aarch64/early_mmu.h`、`hosttests/cases/{test_bootinfo_abi,test_aarch64_boot_layout,test_boot_contract_sequence,test_pmm_boot_reservation}.c`、新 `hosttests/cases/test_aarch64_uefi_rp1_pci.c`。

**Interfaces:**

- 追加 `struct boot_rp1_pci_info`，按以下顺序布置字段。三个 `uint64_t` 为 `bar0_pci, bar0_cpu, bar0_size`，两个 `uint32_t` 为 `table_offset, pba_offset`，两个 `uint16_t` 为 `segment, entries`，四个 `uint8_t` 为 `bus, device, function, msix_cap`。大小 40。记录在 `boot_context.rp1_pci` 的偏移 200。
- `BOOT_CONTEXT_VERSION_RP1_PCI = 4u`，`BOOT_CONTEXT_HAS_RP1_PCI = 1u << 9`。v3 version/size 为 3/200，v4 为 4/240 且 flag 已置位。`boot_context_init()` 默认发布 v3 并清整个编译期结构。新增 `const struct boot_rp1_pci_info *boot_context_rp1_pci(const struct boot_context *ctx)`，仅对合法 v4 返回记录。
- `int uefi_rp1_pci_capture(struct boot_rp1_pci_info *out)`，实现放 `rp1_pci.c`。成功返回 0。无唯一可信匹配返回负值且输出清零。入口只从 aarch64 `arch_fill_firmware()` 的 `rp1-header` 分支调用。

### Task 2 — RP1 拓扑、共享 PCI 访问与预映射

**Files:** `kernel/arch/aarch64/platform/{dtb_parse_rp1,dtb}.c`、`kernel/arch/aarch64/bus/{rp1_pcie,rp1_pcie_hw}.c`、`kernel/arch/aarch64/driver/rp1_xhci.c`、`kernel/arch/aarch64/boot/main.c`、`kernel/include/arch/aarch64/{rp1_pcie,rp1_xhci}.h`、`hosttests/cases/test_aarch64_rp1_xhci.c` 与新 `hosttests/cases/test_aarch64_rp1_topology.c`。

**Interfaces:**

- `int aarch64_dtb_parse_rp1_irq(const void *blob, uint32_t size, uint64_t selected_gicd, uint64_t console_pa, struct aarch64_rp1_irq_desc *out)`。`struct aarch64_rp1_irq_desc` 的地址字段为 `uint64_t rc_reg_base, rc_reg_size, rp1_child_base, mip_cpu_pa, mip_span, msi_pci_addr, uart_offset`，`uint32_t base_spi, count, offset, uart_source`，`bool valid, uart_valid`。合法 IRQ 控制器可在没有 UART 匹配时提供 `valid=true, uart_valid=false`。
- `const struct aarch64_rp1_irq_desc *aarch64_rp1_irq_desc_get(void)` 返回 DTB 枚举保存的独立对象。DTB 输出错误只让该对象不可用。
- `int aarch64_rp1_pcie_endpoint(const struct aarch64_rp1_irq_desc *desc, const struct aarch64_rp1_pcie_io *io, struct aarch64_rp1_endpoint *out)`。所得字段为 `uint8_t bus, device, function, revision`，`uint64_t bar0_pci, bar0_cpu, bar1_pci, bar1_cpu, outbound_pci_base, outbound_cpu_base, outbound_size`。设备/函数为现有 RC 二级总线预期的 RP1 endpoint，身份通过配置读取确认。
- `void aarch64_rp1_pcie_prepare(const struct boot_context *ctx)` 在原架构 RP1 预映射位置调用。共享对象 `struct aarch64_rp1_irq_platform` 持有经过验证的 IRQ 描述、endpoint、BAR0 记录、RC/MIP/APB/table/PBA 虚拟地址与有界访问接口。`const struct aarch64_rp1_irq_platform *aarch64_rp1_irq_platform_get(void)` 在不可用时返回 NULL。原 xHCI prepare 入口继续消费原 xHCI 数据。
- `enum aarch64_rp1_mmio_space { RP1_MMIO_RC, RP1_MMIO_MIP, RP1_MMIO_APB, RP1_MMIO_TABLE, RP1_MMIO_PBA }`。发布 `int aarch64_rp1_mmio_read32(const struct aarch64_rp1_irq_platform *p, enum aarch64_rp1_mmio_space space, uint32_t off, uint32_t *value)` 与同样前三参数加 `uint32_t value` 的 `aarch64_rp1_mmio_write32()`，检查 dword 对齐、窗口边界，拒绝 PBA 写。`int aarch64_rp1_cfg_read16(const struct aarch64_rp1_irq_platform *p, uint16_t off, uint16_t *value)` 与同样前两参数加 `uint16_t value` 的 `aarch64_rp1_cfg_write16()` 使用探明的 endpoint 和对齐的 16 位访问。`int aarch64_rp1_irq_flush(const struct aarch64_rp1_irq_platform *p, uint32_t source)` 读同一 RP1 endpoint 的指定源 APB RW CFG，完成 posted writes。

- [ ] 在实际 DTB 形状夹具中断言 UART 源 25、level-high、MIP PA `0x1000130000`、消息 `0xfffffff000`、128/64/0。FDT 属性顺序变化时结果相同。对 MIP/GIC 错 phandle、继承 UART parent、RC 选择歧义、offset 越界、错误 PA、禁用 UART 精确匹配及无 xHCI 两种场景分别断言 `valid` 与 `uart_valid`。用两条独立测试证明可选 IRQ 失败不影响 xHCI，xHCI DMA 校验失败不影响独立 IRQ 预映射。
- [ ] 给 endpoint fake MMIO 记录索引、宽度及恢复值。断言读取不会碰 xHCI inbound DMA 寄存器，BDF、revision、BAR0 PCI/CPU 地址、cap 指针或 BIR/offset/数目与 handoff 不符时不访问 table/PBA，跨 2 MiB 的 MMIO 用现有映射验证，重叠 RAM 和越界场景拒绝访问。运行 `make PROFILE=x86_64-clang test-aarch64-rp1-irq-host CASE=topology`，确认用例失败。
- [ ] 在现有 RP1 树上下文中解析 RC、RP1、UART 与 MIP 节点。解析 `reg`、`ranges` 和父中断 phandle 时保留每级地址单元及继承规则。通过经翻译 `reg` 核对 MIP 上游与当前 GICD 是同一控制器。小型描述留在独立 BSS 对象，保有原 `dtb_init` 栈预算。
- [ ] 把 `1de4:0001`、revision 2 身份及 BAR/出站窗核对从 xHCI DMA 验证拆出。IRQ 路径绑定当前 RC 上的 live BDF、固件 BAR0 PCI/CPU 地址对及实际 capability。UEFI segment 用于取证，v0.3 DTB 未提供可与之比较的域，身份以 live RC、BDF 和地址对确认。保留旧公开 `aarch64_rp1_pcie_resources()` 入口和 xHCI 宿主夹具。共享硬件访问一次事务保存并恢复索引，同一把锁覆盖选槽及读写，32 位 RC 寄存器与 16 位 PCI Message Control 分别访问，临界区不等待 IRQ。
- [ ] 在 Stage 3 加载共享 platform 对象，复用 `aarch64_boot_mmio_ctx_init()` 和 `aarch64_boot_mmio_map()`。表/PBA 距离和长度按 handoff 的 BAR0 授权范围、实际 capability 及桥窗重新校验。BAR1 基址加 `0x108000` 起的完整 4 KiB 经同样的映射检查。验证构建输出 `[rp1-irq-topology] rc=... mip=... source=... spi_base=... count=... offset=...` 与 `[rp1-irq-bar0] bdf=... pci=... cpu=... size=... table=... pba=...`，用 OS01 logger 支持的格式。IRQ 对象准备失败后仍执行原 xHCI 准备。不在 Stage 7 做新的页表映射。重复 `make PROFILE=x86_64-clang test-aarch64-rp1-irq-host CASE=topology`，确认 xHCI 旧夹具与新增拓扑测试 PASS。提交 `aarch64: discover and map RP1 interrupt resources`。

### Task 3 — BCM2712 入站门铃与 MIP 槽

**Files:** `kernel/arch/aarch64/bus/rp1_pcie.c`、`kernel/include/arch/aarch64/rp1_pcie.h`、`kernel/arch/aarch64/intr/{bcm2712_mip,gic_driver}.c`、`kernel/include/arch/aarch64/{bcm2712_mip,gic}.h`、新 `hosttests/cases/test_aarch64_bcm2712_mip.c`、既有 `test_gic_driver.c`。

**Interfaces:**

- `int aarch64_rp1_msi_window_claim(const struct aarch64_rp1_irq_platform *p, struct aarch64_rp1_msi_window *out)` 及 `int aarch64_rp1_msi_window_restore(const struct aarch64_rp1_irq_platform *p, struct aarch64_rp1_msi_window *win)`，保存 slot、是否由本事务编程及四个原始寄存器字。借用现有映射的恢复是空操作。claim 遇到首次编程写入后无法恢复的错误时，记录该窗为内部隔离，设置 `out->quarantined`，返回负值并拒绝后续对该窗的重用。
- `int bcm2712_mip_reserve(const struct aarch64_rp1_irq_platform *p, gic_handler_fn handler, uint64_t param, struct bcm2712_mip_route *out)`，返回记录的 `uint64_t address`、`uint32_t data, intid` 和恢复快照。`int bcm2712_mip_enable(struct bcm2712_mip_route *route)`、`int bcm2712_mip_disable(struct bcm2712_mip_route *route)`（关闭 GIC SPI 并读回，保留所有权供后续静默检查及恢复）、`bool bcm2712_mip_pending(const struct bcm2712_mip_route *route)`、`int bcm2712_mip_clear_probe(struct bcm2712_mip_route *route)`、`int bcm2712_mip_release(struct bcm2712_mip_route *route, bool quiescent)`。release 在不可安全恢复时维持预留并尝试确认上游关闭。reserve 或 enable 发生部分写入后无法恢复时在层内保留隔离槽，并在输出 route 中设置 `quarantined=true`。调用者也保留关联入站路由，避免在上游状态未明时回收。
- 新 GICv2 SPI 操作走受控的 `gic_spi_get_state()` 与 `gic_spi_set_edge()`，分别接收 `struct gic_dev *dev, uint32_t intid` 后加输出 `struct gic_spi_state *out) 或输入 `bool edge`，返回 `int`。状态包含 enable、active、pending、edge、priority、target、group 和 `group_writable`。新增 `int gic_spi_restore_state(struct gic_dev *dev, uint32_t intid, const struct gic_spi_state *saved)`，只对已保留且禁用的 SPI 恢复 trigger、priority、target；group 只在现有 GIC 规则允许写入时恢复，每个字段读回确认。GIC 安全扩展开启时依赖固件组配置。保持现有 `gic_irq_configure()` 调用接口。

### Task 4 — RP1 MSI-X 事务与真实递送探测

**Files:** `kernel/arch/aarch64/intr/rp1_irq.c`、`kernel/include/arch/aarch64/rp1_irq.h`、新 `hosttests/cases/test_aarch64_rp1_irq.c`。

**Interfaces:**

- `typedef void (*rp1_irq_handler_fn)(void *arg)`。设备回调处理并完成清源的 posted writes 后返回。
- `enum rp1_irq_trigger { RP1_IRQ_LEVEL_HIGH, RP1_IRQ_EDGE_RISING }`。
- `int rp1_irq_prepare(uint32_t source, enum rp1_irq_trigger trigger, rp1_irq_handler_fn fn, void *arg, struct rp1_irq **out)` 生成一次启动期事务；`int rp1_irq_commit(struct rp1_irq *irq)` 完成软件状态发布；`int rp1_irq_abort(struct rp1_irq *irq, bool device_mask_verified)` 清理未提交事务。参数为假时强制隔离。返回 0 表示已安全恢复，`-EIO` 表示已确认隔离而保留资源。硬件状态可能活动且所有屏障均无法验证时，调用 `device_fail_unsafe(NULL, "rp1-irq: interrupt containment not verified")`，不返回。prepare 的失败清理使用同一规则。`uint32_t rp1_irq_intid(const struct rp1_irq *irq)` 供诊断。调用者用同一 IRQ-save 临界区覆盖三操作，整个内核中同时只允许一个未提交事务。prepare 返回 0 前确认成功态。GIC SPI 已启用，当前表项 unmasked，RP1 APB ENABLE=1、IACK_EN 与触发类型相符、TEST=0、PBA/GIC pending 清零，调用者设备自己的 IRQ 输出仍为 masked。probe 成功清理不关闭传输层，commit 只发布软件所有权。
- 表项访问使用 `address_low, address_high, data, vector_control` 四个 32 位字段，索引为 `source`。PBA 读取用 `source / 32` 对应的 dword 与位。RP1 APB 每源 `0x08 + 4*source`，SET `+0x800`，CLR `+0xc00`，IACK_EN/IACK/TEST/ENABLE 位依次为 3/2/1/0。
