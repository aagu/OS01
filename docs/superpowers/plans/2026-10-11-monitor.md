# OS01 Terminal Monitor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 每秒在终端显示整体/各核 CPU 利用率、PMM 占用、温度状态与进程 CPU 列表。

**Architecture:** 每核 100Hz tick 累加 busy/idle 和 task runtime；procfs 在 open 时复制并生成稳定文本，monitor 独立采集、差分和渲染。第一阶段 thermal facade 返回 unsupported；真实 Intel 采集由独立 thermal 计划交付。

**Tech Stack:** freestanding C、Clang/LLD、OS01 VFS/procfs、spinlock/atomic、hosttests、QEMU Python harness、VT100。

**Spec:** `docs/superpowers/specs/2026-10-09-monitor-design.md`（提交 `f0a1020`）。用户于 2026-10-11 选择终端界面；不实现 libgfx renderer。

## Global Constraints

- 当前所有核为 `100Hz`；首轮、计数回退、epoch 改变或分母为零显示 `--`。
- `100%` 表示一个逻辑 CPU 满载；双核一核满载整体约 `50%`。
- 整数显示以 `10000` 表示 `100.00%`，中间乘法用 `__uint128_t`，显示时四舍五入到一位小数。
- `comm[64]`，长度最多 `63` 字节；Name 编码必须在内核序列化时完成。
- `NOFILE=16`；每个 PID 单独打开、读完、关闭；历史键为 `(pid, birth_id)`。
- 主卡使用 `T/U/F` 同一 `pmm_lock` 快照；池内可复用空间不能标成 MemFree。
- 修改 `task_t/file_t/VFS` 结构后 `make clean`；源目录/公开头目录成对。
- 第一版只声明 x86_64 已验证；AMD/aarch64/hypervisor 温度返回 unsupported，不使用假温度。
- CPU/内存历史保留 `60` 个时间槽，缺失样本为空点；单调 deadline 每秒一次，不忙循环补采。
- 不新增 RSS、完整命令行、全局任务快照 syscall、图形版或空池回收。

## Review Focus

- tick 启动失败或重置：对应核 unavailable，不能贡献伪零值（Task 2）。
- 分段 read/dup/fork/失败 open：文本固定，释放恰一次，错误不泄漏（Task 1）。
- 名称注入和字段重复：编码保持单行，解析拒绝伪造必需键（Tasks 4/6）。
- 动态任务目录及 PID 重用：不悬空解引用、不合并旧进程 CPU 历史（Tasks 4/7）。
- 退出/信号/采样延迟：恢复终端、释放 fd，历史不填伪零、不补采（Task 8）。
