# x86_64 Kernel Stack Protector Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable reliable x86_64 kernel stack-protector instrumentation with direct canary accesses and prove it in build and QEMU acceptance paths.

**Architecture:** The x86_64 kernel switches from PIE to a fixed-address static code-generation model while preserving `-mcmodel=kernel`, then enables `-fstack-protector-strong`.  A Python audit validates direct `PC32` canary relocations in `sched/task.o` and real call sites to the final image's failure handler.  A distinct canary-selftest build variant deliberately corrupts a protected frame and must halt through the existing handler.

**Tech Stack:** GNU Make, Clang/LLVM (`llvm-readelf`, `llvm-objdump`), freestanding C11, Python 3, x86_64 QEMU/OVMF.

**Spec:** `docs/superpowers/specs/2026-09-11-x86_64-kernel-ssp-design.md`

## Global Constraints

- Apply only to `ARCH=x86_64`; do not change aarch64, userland, libc, the linker load address, or the runtime provider's separate `-fno-stack-protector` flags.
- Preserve `-mcmodel=kernel` and the existing global `__stack_chk_guard` / non-instrumented `kernel_main` and `__stack_chk_fail` contract.
- Replace `-fpie` with `-fno-pic`; do not attempt a GOT/linker-relaxation workaround.
- Build audit must reject a `__stack_chk_guard` GOT relocation and require a direct `R_X86_64_PC32` relocation in the selected large object.
- Every compiler-flag transition requires `make clean` before an acceptance build because Makefile header dependencies do not cover flag changes.
- The intentional overflow is compile-time gated, isolated in its own kernel artifact variant, and never enabled in ordinary/selftest/syscall images.

def run_tool(tool: str, args: list[str], label: str) -> str:
    result = subprocess.run([tool, *args], text=True, capture_output=True,

### Task 4: Add an isolated destructive canary acceptance variant

**Files:**
- Modify: `mk/profiles/x86_64-clang.mk:23-25`
- Modify: `kernel/Makefile:105-113`
- Modify: `kernel/kernel/main.c:104-126`

**Interfaces:**
- Consumes: `KERNEL_CANARY_SELFTEST=1`, existing `__stack_chk_fail`, and `write_serial` diagnostics.
- Produces: a separate `kernel/canary-selftest` artifact whose boot deliberately reaches `__stack_chk_fail` before normal subsystem initialization.

- [ ] **Step 1: Make the artifact namespace unambiguous**

Replace the one-level `KERNEL_VARIANT` expression in
`mk/profiles/x86_64-clang.mk` with:

```make
ifneq ($(filter 1,$(KERNEL_SELFTEST)),)
ifneq ($(filter 1,$(KERNEL_CANARY_SELFTEST)),)
$(error KERNEL_SELFTEST=1 and KERNEL_CANARY_SELFTEST=1 are mutually exclusive)
endif
KERNEL_VARIANT := selftest
else ifneq ($(filter 1,$(KERNEL_CANARY_SELFTEST)),)
KERNEL_VARIANT := canary-selftest
else
KERNEL_VARIANT :=
endif
```

This keeps ordinary, selftest, syscall, and destructive-canary object trees separate.

- [ ] **Step 2: Define the compile-time gate only in the kernel**

After the DEBUG/NDEBUG block in `kernel/Makefile`, add:

```make
ifneq ($(filter 1,$(KERNEL_CANARY_SELFTEST)),)
ALL_CFLAGS += -DOS01_CANARY_SELFTEST
endif
```

Do not export this define to libc, BusyBox, UEFI, or normal image builds.

- [ ] **Step 3: Implement the controlled protected-frame overwrite**

Before `kernel_main` in `kernel/kernel/main.c`, add:

```c
#ifdef OS01_CANARY_SELFTEST
__attribute__((noinline))
static void kernel_canary_selftest_trip(void)
{
    volatile char buffer[16];
    for (unsigned int i = 0; i < 32; ++i)
        ((volatile char *)buffer)[i] = (char)i;
}
#endif
```

Immediately after `kernel_main` seeds `__stack_chk_guard`, add:

```c
#ifdef OS01_CANARY_SELFTEST
    kernel_canary_selftest_trip();
    __builtin_unreachable();
#endif
```

The function is deliberately `noinline` so it owns the protected frame.  The
volatile writes preserve the overwrite through optimization; the compiler's
stack-protector epilogue must call the existing failure handler.  This code is
unreachable in every build that does not explicitly set the gate.

- [ ] **Step 4: Build and boot the destructive variant**

Run:

```bash
make clean
make PROFILE=x86_64-clang KERNEL_CANARY_SELFTEST=1 image
```

Then resolve the profile paths and boot headless:

```bash
FW=$(make -s PROFILE=x86_64-clang KERNEL_CANARY_SELFTEST=1 print-run-paths | sed -n 's/^firmware=//p')
IMG=$(make -s PROFILE=x86_64-clang KERNEL_CANARY_SELFTEST=1 print-run-paths | sed -n 's/^image=//p')
timeout 35 qemu-system-x86_64 -M q35 -smp 1 -m 512 -display none -serial stdio \
  -drive if=pflash,format=raw,readonly=on,file="$FW" \
  -drive file="$IMG",format=raw,if=none,id=disk -device ahci,id=ahci \
  -device ide-hd,drive=disk,bus=ahci.0 > /tmp/os01-canary-selftest.log 2>&1 || true
rg -F '*** Kernel stack smashing detected ***' /tmp/os01-canary-selftest.log
```

Expected: `rg` finds exactly the handler banner.  QEMU timing out is expected
because the handler halts permanently.
