# D05 — Doom IWAD 打包 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 显式校验并打包本地 IWAD，保证镜像内容与资源选择一致。

**Architecture:** 脚本产生profile私有校验制品，rootfs manifest消费制品。四变量全空保留无资源构建；资源变化通过内容摘要失效。

**Tech Stack:** freestanding C、Clang/LLVM、GNU Make、现有 hosttests/Python harness。

**Spec:** [Doom IWAD 打包](../specs/2026-11-10-doom-05-assets-design.md)。状态：文档评审通过，全部步骤未执行。

**前置：** 依赖现有rootfs构建；无需D04已可运行，测试用假数据不得当作游戏兼容证据。

## Global Constraints

- 遵守[总览公共约束](../specs/2026-11-10-doom-port-design.md)；仅根 make、profile 私有产物，不覆盖已有工作区修改。
- 四变量DOOM_IWAD/DOOM_IWAD_SHA256/DOOM_IWAD_LICENSE/DOOM_IWAD_SOURCE成组提供。
- 默认无WAD且不联网；无Git WAD二进制；目标/usr/share/games/doom/iwad.wad。
- 不直接改变引擎编译键，不以shell拼接解释来源文本。

## Review Focus

- 半组、目录、错误哈希必须失败 → T1。
- 路径分隔符/空白不被静默拆词 → T1。
- 来源含空格/引号/美元符/反引号在脚本与根 Make 路径均保持原文 → T1/T2。
- 同路径内容或许可证变化要失效 → T2。
- 移除资源变量后新镜像无残留 → T2。

**Interfaces:** 产生 manifest 三条目标路径和真实资源 prerequisites/stamp；根镜像层用简单展开的专用导出环境变量传值，`$(value DOOM_...)` 只取原始值，调用脚本 `--from-env`，不把四变量加入 OS01_SUBMAKE_ARGS，不在 shell 命令正文插值用户字符串。保留 image 只消费制品的边界。

- [x] 写测试：`same_path_bytes_change` 新哈希/字节触发重打包；`license_change`触发更新；`unchanged_stamp_stable`不反复更新；`remove_inputs_no_residue` 清空变量后新manifest/镜像无WAD。另由 Python subprocess 参数数组调用真实仓库根 Make 的资源制品 target（位于 profile 私有 build 目录、无需先构建内核/游戏）：`root_make_source_literal` 传包含空格、单双引号、美元符、反引号、分号及字面 Make 函数语法的来源，输出原文且无任何命令执行 sentinel；`root_make_partial_inputs_fail` 逐项缺失均非零，资源 stamp/manifest/镜像未发布。不用假 Makefile 或仅脚本 CLI 测试代替这一路径。
