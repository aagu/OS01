# Craton/OS01 x86_64 PT_TLS 最小支持实施计划

> 实施时使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，逐项勾选。本文的命令与提交步骤仅供后续实现使用。

**目标**　让 TinyGo 类静态产物在 Craton x86_64 用户态用 8 字节 TLS、`ARCH_SET_FS` 和 `ARCH_GET_FS` 运行，并在调度、fork 和 exec 中维持 FS 状态及映像隔离。

**架构**　原生与 Linux 兼容 syscall 共用 x86 misc handler。ELF 装载器在未发布 mm 内安装匿名私有 TLS VMA，将 TP 交给 spawn 与 staged exec。

**技术栈**　x86_64 C/汇编、ELF64、Clang/LLD、宿主测试、QEMU systest。

**设计依据**　[2026-11-24-ptls-x86_64-design.md](../specs/2026-11-24-ptls-x86_64-design.md)。源码锚点以基线 `a9771444` 为准，新增文件及符号在下文显式标明。

## 全局约束

- 单个主程序、单个用户执行线程、单个非空 PT_TLS，兼容静态 ET_EXEC 和当前白名单的静态 PIE。TLS 使用 Variant II，整个页取整跨度上限为 64 KiB。保持无 TLS ELF 的现有装载和地址空间行为。
- 原始 syscall 使用原生 79、Linux 158、SET 0x1002、GET 0x1003。GS、aarch64、clone、动态 TLS、CRT 与产品 linker script 留在本期范围外。公开 libc wrapper 是设计中的独立用户决策项。
- 每个任务依次完成 RED、实现、GREEN、顶层 systest 回归，所有检查通过后单独提交一个修复。每次提交只暂存该任务的实现、测试和必要的测试目录生成物。手写宿主注册表禁止，新增独立宿主 case 时走 `@os01-test` 和 `make regen-test-catalog`。不改 AGENTS.md，不改 thirdpart，不 push。
- 每个 syscall E2E 运行命令使用顶层 `make OS01_SYSTEST=1 test-syscall`，始终与 `KERNEL_SELFTEST=1` 分离。依据：[AGENTS.md:15](../../../AGENTS.md#L15)、[AGENTS.md:16](../../../AGENTS.md#L16)、[mk/components/run.mk:1625](../../../mk/components/run.mk#L1625)。

## 评审重点

- 任务 1 检查完整 64 位操作码和合法但未映射的最大低半地址，避免截断后误写 MSR。
- 任务 1 检查 GET 跨两个 COW 叶、第二页不可写、以及只读目的页，防止错误地绕过 uaccess。
- 任务 2 检查非零 ELF 对齐余数和 TinyGo 样本形状的纯 `.tbss`，分别阻止 TP 位移错误和空模板文件读取。
- 任务 2 检查 TLS 目标已有 2 MiB 叶、PROT_NONE PTE 或无 PTE 的 VMA，防止覆盖旧映射。
- 任务 2 用不同的新旧 FS base 指纹检查 exec 回滚、重建和清零，避免同一固定 TP 地址掩盖缺陷。

## 任务 1 — 原始 arch_prctl、FS 切换与 fork 继承

预计约 **250 行，±50%**，含生产代码、宿主断言和 QEMU 探针。

**接口**　现有 `int64_t sys_misc_dispatch(syscall_ctx_t *ctx)` 添加一个 case。新增 x86 私有 `uint64_t x86_read_fs_base(void)`、`void x86_install_current_user_fs(thread_t *thread, uint64_t base)`、`void x86_snapshot_user_fs(thread_t *child_thread)`，声明放在 `context.h`，实现在 `cpu/switch.c`。安装函数要求调用者关本地 IRQ，并给出已验证的用户 base。快照函数自行保存与恢复 IRQ 状态，写子任务上下文。任务 2 调用安装函数。

- [ ] **RED — 入口与真实 FS 测试。** 宿主套件用字面 79 检查 full table 的名字 `arch_prctl`、misc handler 收到参数不变，以及 aarch64 subset 无 handler。兼容套件用字面 158 验证 nr 重映射 79、选项和值不变，并保留既有 56→fork 断言。QEMU 中登记 `arch_prctl_fs`，先 GET 保存原值，再用两个不同的用户地址或未映射值 SET，验证 GET 与对已映射测试字的 `%fs:0` 读取。核对 SET 0、上界 `0x00007FFFFFFFFFFF`、越界 `0x0000800000000000`、高半 `0xFFFF800000000000`、未知操作和 `0x100001002`，每次错误后 GET 仍给出前值。GET 覆盖 NULL、只读和跨页第二页不可写的目标。另用两个私有可写页，在 fork 后从子进程 GET 跨页写 8 字节，父进程哨兵不变。用管道握手实际让父子阻塞并恢复，验证继承的 base、各自 SET 后的 base 和正向 FS 读数。保留 runnable 各分支的有界等待及 `waitpid` 退出检查。Linux GNU ABI note 探针用原始 158 执行 SET/GET/清零，并用该探针已有的退出状态反馈结果。
- [ ] **确认 RED。** 跑 `make test-host`、`make OS01_SYSTEST=1 test-syscall CASE=arch_prctl_fs` 和 `make OS01_SYSTEST=1 test-syscall CASE=54_linux_abi_compat`。预期宿主报告 79 缺少 handler、158 未映射，QEMU 首次原生 GET 返回 `-EINVAL`、兼容 GET 返回 `-ENOSYS`。单用例入口见 [mk/components/run.mk:1464](../../../mk/components/run.mk#L1464)。用字面编号启动 RED，新增生产宏和结构成员后再切换测试引用及加入布局断言。编译失败、夹具未运行或整套超时不能充当行为 RED。
- [ ] **实现。** 追加带编号校验的宏并把 x86 原生表上界扩张到新编号，在 full block 注册并实现 misc case。SET 在验证范围后以 `arch_local_irq_save/restore` 包住 x86 安装函数。GET 读取 live MSR，再用 `copy_to_user_ft` 写 8 字节并传递负值。对任意未知选项返回 `-EINVAL`。在 `thread_t` 末尾新增 FS base 字段及偏移/大小断言，更新原有宿主布局用例为 80/88，并保留此前所有固定值。切出读 MSR，再存旧选择子。切入先恢复选择子再写 MSR，保存点在 `task_switch_complete` 前。SET 先写选择子 0 再写 MSR，同步保存值。fork 在当前写子选择子的地点读 live 快照，保证在入队前得到一致快照。BSP 静态初值、AP idle 与新 kthread 的零初始化覆盖新字段，检查 [kernel/arch/x86_64/cpu/task_arch.c:43](../../../kernel/arch/x86_64/cpu/task_arch.c#L43)、[kernel/arch/x86_64/smp/smp.c:186](../../../kernel/arch/x86_64/smp/smp.c#L186)、[kernel/sched/kthread.c:171](../../../kernel/sched/kthread.c#L171)。Linux 表增加 158→79，现有重映射代码无需独立适配器。
- [ ] **GREEN。** `make test-host` 中原生表、subset、兼容表、布局测试全绿。重跑 RED 的两个 `CASE` 命令，两条 QEMU 探针都须通过。核查 raw GET 安全写入走 uaccess 的错误返回与 COW 准备路径，GET 的 8 字节即使跨页也使用同一调用。依据：[kernel/arch/x86_64/memory/uaccess.c:61](../../../kernel/arch/x86_64/memory/uaccess.c#L61)、[kernel/arch/x86_64/memory/uaccess.c:241](../../../kernel/arch/x86_64/memory/uaccess.c#L241)。

## 任务 2 — 装载静态 TLS 并在 spawn/exec 交付

预计约 **520 行，±50%**，含装载与 handoff、宿主故障注入、用户夹具和安装规则。

**接口**　复用现有 `elf_load(vfs_node_t *, mm_t *, x86_elf_image_t *)`，成功输出新增 `uint64_t fs_base`。在 `elf.c` 内部新增 `static int x86_elf_tls_describe(const elf64_ehdr_t *ehdr, const elf64_phdr_t *phdrs, uint64_t file_size, x86_elf_tls_t *out)` 和 `static int x86_elf_tls_map(mm_t *mm, uint64_t bias, const x86_elf_tls_t *tls)`。私有 `x86_elf_tls_t` 的成员均为 `uint64_t`，含 `image_vaddr`、`filesz`、`block_start`、`fs_base`、`map_end`。以 `fs_base == 0` 表示无 TLS，此时 map 返回 0，不分配。exec 消费任务 1 的 `x86_install_current_user_fs(thread_t *, uint64_t)`。

- [ ] **RED — 真实 loader 和 handoff 断言。** 在现有宿主页账本加 TLS 夹具。对 ET_EXEC 设 `A=64, r=16, memsz=17`，断言单独匿名页、`TP=0x20600040`、模板从 `0x20600010` 开始、初始化值、零尾和 TP 自指针。分别用 `p_align=0/1`（`memsz=9`，TP `0x20600010`，模板起点 `0x20600007`）、TinyGo 0.44.0 样本形状的 ET_EXEC 纯 `.tbss`（`p_memsz=8`、`p_filesz=0`，偏移可取 `UINT64_MAX`，8 字节全部为零且无模板读取）、源及目的跨页测试模板复制。在 `A=1` 时，`memsz=65528` 的跨度恰为 64 KiB，`memsz=65529` 则超限。加静态 PIE 偏置夹具，在可写文件模板内用对齐的 RELATIVE 槽写 `bias+addend`，校验复制的是修正值，旧的非 RELATIVE 仍拒绝。重复/空头、非法对齐、`filesz>memsz`、范围/加法溢出、偏移不一致与非覆盖模板、带 TLS 的 ET_EXEC + PT_INTERP/PT_DYNAMIC 都断言 `-ENOEXEC`、无映像叶、无输出修改。测试中通过原有返回值及页账本先取得 RED，新增字段后加 handoff 断言。
- [ ] **RED — 回滚和用户进程生命周期。** 对初始化数据短读、VMA 节点分配失败、第一及后续 TLS 物理页分配失败、首个 TLS 叶的中间页表分配失败分别注入。固定 TLS 区间内各叶共用同一 PTE 表，另用宿主 `x86_vmm_map_4k` 替身模拟第二次映射调用失败，以覆盖已有一个 TLS 叶的通用回滚。两类建页测试的依据见 [kernel/arch/x86_64/memory/vmm.c:255](../../../kernel/arch/x86_64/memory/vmm.c#L255)。对各注入点核对 `-ENOEXEC/-ENOMEM`、无孤儿 VMA、叶释放计数与 TLS 目标区的哨兵 PTE。预置目标区的 2 MiB 叶、PROT_NONE 叶或无 PTE 的 VMA，验证这些结构及其数据不变。spawn/exec 宿主夹具记下 FS 安装调用和入队状态，覆盖 spawn 不写创建者 FS、exec 成功安装到新 mm/CR3 后且 IRQ 恢复前、及装载/后续 staged 失败不安装也不退役旧 mm。
- [ ] **RED — 实际 ELF。** 同一份夹具源码分别用 `-ftls-model=local-exec -fno-stack-protector` 构建成固定地址与静态 PIE。固定地址分支的 `current_task` 是唯一一个 8 字节、8 字节对齐的零初始化 `_Thread_local` 对象，PIE 分支同时验证初始化与零值对象。入口调用 C 探针，先读对象，再核对取地址和 `%fs:0`。对 `ptls_exec` 用 `readelf -l` 断言 `p_memsz=8`、`p_filesz=0`、`p_align=8` 且 `p_vaddr` 按 8 对齐。探针先通过 GET 保存初始 TP，在自管的 8 字节对齐的两字用户块中放入不同的 `current_task` 哨兵和 TP 自指针。通过 SET 将 FS base 设为第二字地址，GET 读回该地址，然后用实际 local-exec 访问读取和改写第一字。再 SET 恢复原 TP，核对原 `current_task` 未受影响并正常退出。使 TLS 对象的读写可观察，避免编译器消除 FS 访问。测试专用 linker scripts 显式给 `.tdata` 同时分配数据 PT_LOAD 和 PT_TLS，`.tbss` 使用 NOLOAD 并纳入 PT_TLS。PIE 使用仓库约束的无解释器、4 KiB 最大页、`-z text`、`-z norelro`、`--pack-dyn-relocs=none`，两个 PT_LOAD 的页范围互不相交，从链接 VA 0、文件偏移 0 的可读非写 LOAD 开始并覆盖 ELF 头及 PHDR 表。唯一 PT_DYNAMIC 须完全包含在文件支持的 RW/NX LOAD 中，并含 `DT_FLAGS_1/DF_1_PIE` 及 `DT_NULL`。依据：[kernel/arch/x86_64/fs/elf_pie.c:165](../../../kernel/arch/x86_64/fs/elf_pie.c#L165)、[kernel/arch/x86_64/fs/elf_pie.c:197](../../../kernel/arch/x86_64/fs/elf_pie.c#L197)、[kernel/arch/x86_64/fs/elf_pie.c:330](../../../kernel/arch/x86_64/fs/elf_pie.c#L330)。用同一 C 源的无 TLS 编译分支和 [libc/arch/x86_64/user.ld:5](../../../libc/arch/x86_64/user.ld#L5) 链接 `ptls_plain`，入口只检查 GET=0。用 `readelf -l` 确认该产物无 PT_TLS。通过 `readelf -h -l -d -r` 与 `llvm-objdump -d` 对产物核对类型、PT_TLS、动态白名单和带 FS 位移的真实访问。将三个文件装入 x86 systest 镜像后登记 `pt_tls_exec`，用 fork/exec 等待探针退出，检查首次初始化、fork 继承父亲写入值、双方改写隔离、失败 exec 后旧值及手工 FS、TLS→TLS exec 恢复模板和 TLS→`ptls_plain` 清零。建立明确的失败退出码，区分加载拒绝、错误模板和缺页杀死。
- [ ] **确认 RED。** `make test-host` 应在 TLS 页内容或畸形 ET_EXEC 校验断言失败，同时静态 PIE TLS 被拒。顶层 `make OS01_SYSTEST=1 test-syscall CASE=pt_tls_exec` 应在 TLS 程序入口或 PIE 装载断言失败。核对夹具确已构建、安装和执行。
- [ ] **实现 — 校验和描述。** 在 `elf_load` 读取 PHDR 前检查其表范围，既有 ET_EXEC/PIE 校验后、PIE 取熵前调用 `x86_elf_tls_describe`。PIE 采用已验证的段列表，移除校验器对 PT_TLS 的直接拒绝，并保留其对其余 PHDR、动态表、重定位的约束。单次扫描确定 PT_TLS 和 ET_EXEC 禁止头，按设计检查窗口、文件与 PT_LOAD 对应关系、对齐余数、页取整和 64 KiB 上限。全部结果仅写到 loader 的临时描述。
