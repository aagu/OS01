# D01 — Doom 前置 libc 补充 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 独立补齐标准头、abs 家族、fabs 和 remove，保持 libc/libk 消费者兼容。

**Architecture:** 复用现有 stdio、syscall 和 API 审计。格式宏进入 stdio 私有头；fabs 采用 binary64 位操作的头内实现；remove 使用 lstat 分类。

**Tech Stack:** freestanding C、Clang/LLVM、GNU Make、现有 hosttests/Python harness。

**Spec:** [Doom 前置 libc 补充](../specs/2026-11-10-doom-01-libc-design.md)。状态：文档评审通过，全部步骤未执行。

**前置：** 无 Doom 依赖；D01 可独立实施和合入。

## Global Constraints

- 遵守[总览公共约束](../specs/2026-11-10-doom-port-design.md)；仅根 make、profile 私有产物，不覆盖已有工作区修改。
- 已有 fseek/ftell、scanf %i/%o 不重写；不实现 system/fscanf/libm。
- 新 libc 私有头留在 libc/include/<模块>/；不让 __is_libk 对象发用户 syscall。
- 生产测试符号重命名，不能落到宿主 abs/fabs/remove；fabs 不要求外部导出。

## Review Focus

- 头的双 TU/C++ linkage 与历史 unistd 声明兼容 → T1。
- 迁移 do_div 后两架构和浮点 printf 不退化 → T1。
- 负零/NaN/无穷和 -fno-builtin 调用不递归 → T2。
- symlink 指向目录时仅删除链接 → T3。
- lstat/删除失败的 errno 和非空目录保持正确 → T3。

**Files:** 修改 `libc/include/{stdio,stdlib,sys/stat}.h`、`libc/include/stdio/internal.h`、`libc/stdio/{vsprintf,floatconv}.c`、`scripts/audit_libc_api.py`；新增 `libc/include/strings.h`；扩展 `hosttests/cases/test_libc_api.c`、`hosttests/mk/libc.mk`。

**Interfaces:** 消费现有 strcasecmp/strncasecmp/rename/mkdir 实现；产生标准位置声明、无 LEFT 等污染的 stdio 公共头。

- [ ] 写测试：`stdio_namespace_clean` 编译 enum { LEFT=1 } 成功；`standard_header_two_tu` 从标准位置取函数指针且链接无重复定义；C++ linkage 正确。保留既有整数/浮点格式化断言。
- [ ] 运行 RED：`make test-libc-host LIBC_CASE=api`；保存实际失败原因，确认不是其他基线故障。
- [ ] 实现：先增加头编译 probe 并记录缺头/LEFT 冲突 RED；迁移 7 个标志及 do_div/is_digit 到既有 private 头，逐个调整实际消费者。保留 unistd 兼容声明，更新 API 分类而非盲增全量要求。
- [ ] 验证 GREEN：`make test-libc-host LIBC_CASE=api`；`make test-libc-host LIBC_CASE=format`；`make PROFILE=aarch64-clang test-libc-api-audit`。预期目标组全部通过/制品满足断言；真实运行结果单独留证。

### T2：绝对值接口

**Files:** 新增 `libc/stdlib/abs.c`；修改 `libc/include/{stdlib,math}.h`、`scripts/audit_libc_api.py`、`hosttests/cases/{test_libc_integer,test_libc_float_parse}.c` 及 `hosttests/mk/libc.mk` 的对应生产对象规则。

**Interfaces:** 产生 int abs(int)、long labs(long)、long long llabs(long long) 和 math.h 的 static inline double fabs(double)。

- [ ] 写测试：`integer_abs_values` 断言 -7/0/7；`fabs_bit_contract` 断言 -0.0→+0.0、-Inf→+Inf、NaN payload 保留且符号清零；-fno-builtin 两 TU probe 可链接。
- [ ] 运行 RED：`make test-libc-host LIBC_CASE=integer`；`make test-libc-host LIBC_CASE=float`；保存实际失败原因，确认不是其他基线故障。
- [ ] 实现：记录缺接口 RED，新增非递归 abs 家族；fabs 用 uint64_t 联合体清符号位，不改既有 signbit/isfinite 宏。测试时统一重命名声明与生产定义，禁止宿主兜底。
- [ ] 验证 GREEN：`make test-libc-host LIBC_CASE=integer`；`make test-libc-host LIBC_CASE=float`；`make test-libc-api-audit`。预期目标组全部通过/制品满足断言；真实运行结果单独留证。

### T3：remove 的真实路径语义

**Files:** 新增 `libc/stdio/remove.c`；修改 `libc/include/stdio.h`、`scripts/audit_libc_api.py`、`hosttests/cases/test_libc_path.c`、`hosttests/mock/libc_path_runtime.c`、`hosttests/mock/libc_path_runtime.h`、`hosttests/mk/libc.mk`。测试链接生产 `libc/stdio/remove.c`、`libc/unistd/unlink.c`、`libc/unistd/rmdir.c` 和既有 lstat wrapper；为新增对象登记独立编译规则与统一符号重命名，不修改删除 wrapper 的产品语义。

**Interfaces:** 消费 lstat/unlink/rmdir；产生 int remove(const char *path)，成功0，失败-1/errno。

- [ ] 写测试：`remove_regular_file` 返回 0、调用一次 unlink 且节点消失；`remove_empty_dir` 返回 0、调用一次 rmdir 且目录消失；`remove_directory_symlink` 只 unlink 链接、目标目录仍存在；`remove_nonempty_dir` 返回 ENOTEMPTY 且目录/子项不变；`remove_lstat_failure` 保留 ENOENT/EACCES 且删除调用数为 0；`remove_unlink_failure`/`remove_rmdir_failure` 保留各自 errno 且节点不变。
- [ ] 运行 RED：`make test-libc-host LIBC_CASE=path`；保存实际失败原因，确认不是其他基线故障。
- [ ] 实现：在 path runtime 的 `host_test_syscall_ext` 增加 SYS_unlink/SYS_rmdir 分支、调用记录、成功节点移除及按调用注入错误；通过现有统一 syscall hook 连接，不另建会冲突的 hook。测试 TU、remove/lstat/unlink/rmdir 生产对象的重命名一致，检查链接符号防止宿主兜底。记录缺符号/行为 RED，再按 lstat 类型实现一次删除操作；用户态实现与 __is_libk 隔离，mock 仅替换 syscall 边界。
- [ ] 验证 GREEN：`make test-libc-host LIBC_CASE=path`；`make test-libc-api-audit`；`make PROFILE=aarch64-clang test-libc-api-audit`。预期目标组全部通过/制品满足断言；真实运行结果单独留证。
- [ ] 审阅差异并提交本任务明确文件，提交信息：`feat(libc): implement remove with file and directory semantics`。
