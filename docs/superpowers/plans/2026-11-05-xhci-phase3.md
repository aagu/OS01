# xHCI Phase 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement xHCI Phase 3: full USB Configuration Descriptor hierarchy retrieval (two-stage), dynamic endpoint ring allocation (`struct xhci_ep_ring **ep_rings`), `Configure Endpoint` command (TRB Type 12) with accurate Interval calculation, and 2-stage `SET_CONFIGURATION` control transfer to transition devices into the Configured state on QEMU xHCI.

**Architecture:** Extend `kernel/driver/xhci.c` and `kernel/include/driver/xhci.h`. Implement two-stage configuration descriptor reading with short-packet handling and defensive bounds checks. Strictly follow the user requirement: dynamically allocate `slot->ep_rings` sized to `(max_dci + 1)` pointers without static pre-allocation. Implement `xhci_free_endpoint_rings` for leak-free OOM rollback and device removal. Calculate xHCI Interval exponents ($2^{\text{Interval}-3} \times 1\text{ms}$). Populate Input Context with Slot Context (`Context Entries = max_dci`) and Endpoint Contexts for discovered DCIs, issue `Configure Endpoint` command (Type 12), and complete 2-stage zero-length `SET_CONFIGURATION` control transfer.

**Tech Stack:** C (Clang, freestanding kernel runtime, -O2), x86_64 higher-half MMIO, QEMU xHCI emulation (`-device qemu-xhci,id=xhci -device usb-tablet,bus=xhci.0`), OS01 hosttest test harness.

**Spec:** `docs/superpowers/specs/2026-11-05-xhci-phase3-design.md`

## Global Constraints
- Freestanding C runtime: no standard libc headers in kernel space; use `<memory/slab.h>` (`kmalloc`/`kfree`), `<memory/pmm.h>` (`alloc_4k_page`/`free_4k_page`), `<log/log.h>`.
- **Memory Contract**: `alloc_4k_page()` returns physical address (`uint64_t`). Dereferencing requires `Phy_To_Virt(phys)`. `free_4k_page(phys)` accepts physical address (`uint64_t`).
- **Dynamic Endpoint Rings Contract**: `ep_rings` must NOT be a fixed array. It must be dynamically allocated as `struct xhci_ep_ring **ep_rings` sized to `sizeof(struct xhci_ep_ring *) * (max_dci + 1)` and freed cleanly via `xhci_free_endpoint_rings()`.
- All register and TRB structures must be packed (`__attribute__((packed))`).
- Every test in `hosttests/cases/test_xhci_phase3.c` must be runnable with standard `TEST_SUITE` / `assert_eq` macros.
- All hosttests must run cleanly under `make test-host` without warnings or leaks.

## Review Focus
1. Memory safety & OOM rollback: if `alloc_4k_page()` or `kmalloc()` fails during endpoint ring allocation, `xhci_setup_endpoint_rings` must roll back all allocated pages and structures without leaking.
2. Short packet & residual handling in two-stage GET_DESCRIPTOR: clamp valid parse length to $\min(\text{actual}, w\text{TotalLength})$ with minimum length check $\ge 9$.
3. Malformed descriptor protection: sub-descriptor length underflow (`len < sizeof(...)`), `ep_num == 0` guard, DCI range check ($2 \le \text{DCI} \le 31$), and duplicate endpoint definition prevention.
4. Interval calculation: $2^{\text{interval}-3} \times 1\text{ms}$ for Full/Low-speed Interrupt endpoints ($bInterval=10 \to \text{interval}=6$, meaning 8ms).
5. Two-stage `SET_CONFIGURATION`: Setup Stage TRB `TRT = 0` (No Data Stage), `IDT = 1`, followed directly by Status Stage TRB `DIR = 1` (IN), `IOC = 1`.

void test_xhci_parse_config_descriptor_hierarchy(void)
{
    TEST_CASE("Parse valid USB Configuration Descriptor hierarchy (Tablet HID)");
    struct xhci_slot slot;
    memset(&slot, 0, sizeof(slot));
    slot.speed = XHCI_PORT_SPEED_FULL;

    /* Raw descriptor hierarchy for QEMU usb-tablet:
     * Config (9B): total_len=34, 1 iface, config_val=1
     * Interface (9B): iface=0, alt=0, eps=1, class=3 (HID), subclass=0, proto=0
     * HID (9B): desc_len=9, type=0x21
     * Endpoint (7B): addr=0x81 (EP1 IN -> DCI 3), attr=3 (Intr), mps=8, interval=10
     */
    uint8_t raw_desc[34] = {
        /* Config */
        9, USB_DESC_TYPE_CONFIGURATION, 34, 0, 1, 1, 0, 0x80, 50,
        /* Interface */
        9, USB_DESC_TYPE_INTERFACE, 0, 0, 1, 3, 0, 0, 0,
        /* HID */
        9, USB_DESC_TYPE_HID, 0x10, 0x01, 0, 1, 0x22, 68, 0,
        /* Endpoint */
        7, USB_DESC_TYPE_ENDPOINT, 0x81, 3, 8, 0, 10
    };

    int rc = xhci_setup_endpoint_rings(&slot, raw_desc, sizeof(raw_desc));
    assert_eq(rc, 0);
    assert_eq(slot.max_dci, 3);
    assert_true(slot.iface.active);
    assert_eq(slot.iface.class_code, 3);
    assert_eq(slot.iface.num_endpoints, 1);

    assert_true(slot.ep_rings != NULL);
    assert_true(slot.ep_rings[3] != NULL);
    assert_eq(slot.ep_rings[3]->dci, 3);
    assert_eq(slot.ep_rings[3]->ep_type, XHCI_EP_TYPE_INTR_IN);
    assert_eq(slot.ep_rings[3]->max_packet_size, 8);
    /* For Full-Speed Interrupt with bInterval=10, 2^(6-3) = 8ms <= 10ms -> interval=6 */
    assert_eq(slot.ep_rings[3]->interval, 6);

### Deviations from this plan (all deliberate, all intentional)

1. **`interval=3` instead of the expected `interval=6`.** The plan's own interval rule
   (§3.3 / Task 2 Step 3) is `High/Super speed: bInterval <= 16 ? bInterval - 1 : 15`.
   QEMU's default `usb-tablet` is a USB 2.0 (High-Speed) device
   (`hw/usb/dev-hid.c`, `usb_version = 2` → `desc_iface_tablet2`) whose interrupt-IN
   endpoint descriptor carries `bInterval = 4`, so the plan's High-Speed rule yields
   `4 - 1 = 3`. The expected `6` belongs to the Full/Low-speed path with
   `bInterval = 10` — the single-unit-test scenario (`slot.speed = XHCI_PORT_SPEED_FULL`),
   which is asserted and passing in `test_xhci_parse_config_descriptor_hierarchy()`.
   The plan's Task 6 expectation list mixes the two paths.
2. **Non-Interrupt endpoints program Interval = 0.** The plan's `xhci_calc_interval()`
   skeleton ignores `ep_type` (which would also trip `-Wunused-parameter` in the
   kernel build, which uses `-Wextra`). Per xHCI 6.2.3.4 the Interval field is only
   meaningful for Interrupt endpoints, so it is now programmed as 0 for every other
   endpoint type.
3. **Endpoint type mapping covers all four transfer types.** The plan only spells out
   Interrupt and Bulk; Isochronous and Control are mapped as well, so an endpoint
   context never carries the "invalid" EP type 0.
4. **`xhci_poll_transfer()` instead of `xhci_poll_event_filtered()`** for the EP0
   transfers. It is the same code path the Phase 2 device-descriptor read already
   uses and additionally filters the completion event by slot id, so a transfer event
   belonging to another slot cannot be mistaken for ours.
5. **`xhci_configure_endpoints()` returns 0 without issuing a command when the device
   exposes no non-EP0 endpoint**, because a Context Entries of 0 is invalid; the EP0
   context programmed by the Address Device command remains the complete device
   context.
6. **The test file also defines `mock_xhci_write32()`.** The plan's test source omits
   it, but the xHCI driver is compiled against `hosttests/mock/arch9/xhci_runtime.h`,
   which redirects every `xhci_write32()` to that symbol — the link would fail
   without it.

### Notes

- The Data Stage TRB transfer length stays in the low bits of `trb->status`
  (`status & 0x1ffff`), matching the Phase 2 device-descriptor path. This is what the
  QEMU xHCI model actually reads (`hw/usb/hcd-xhci.c`, `chunk = trb->status & 0x1ffff`),
  even though the raw xHCI specification text places TRB Transfer Length in bits
  [31:16].
- The Input Control Context Add Flags deliberately contain only the Slot Context and
  the configured endpoint contexts, as the plan's unit test requires. The EP0 context
  in the output device context keeps the value written by the Address Device command.
