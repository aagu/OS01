# xHCI Phase 1（控制器骨架与 DMA 环初始化）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 xHCI 主机控制器驱动阶段一：完成 PCI 探针与绑定、BAR0 MMIO 映射、能力寄存器与 Scratchpad 解析、规范五步软复位握手、DCBAA 与命令环/事件环 DMA 拓扑初始化（包含 Link TRB 与 ERST 配置），并将控制器带入 Running 状态。

**Architecture:** 基于 OS01 ARCH-9 PCI 驱动自注册架构（`.pci_drivers` 节），匹配 xHCI 控制器（0x0C/0x03/0x30）。分配 4KB 页拓扑（DCBAA、带 Link TRB 的 Command Ring、Event Ring 与 ERST），在轮询模式下完成硬件初始化与状态机启动。通过 `hosttests/mk/drivers.mk` 集成宿主单测，全面模拟 MMIO 寄存器交互、Link TRB 回环、超时与故障回退。

**Tech Stack:** C (Clang 15+), x86_64 Higher-Half 内核, PCI Bus Subsystem, PMM 4KB 页分配器, Hosttest 测试框架, QEMU q35。

## Global Constraints

- **内核目录与头文件对称**：驱动头文件必须为 `kernel/include/driver/xhci.h`，实现为 `kernel/driver/xhci.c`，遵循单一根 `-Iinclude` 解析。`kernel/Makefile` 自动通过 `wildcard driver/*.c` 发现，无需冗余注册。
- **内存分配规范**：物理页分配使用 `alloc_4k_page()`，释放使用 `free_4k_page()`，访问必须经 `Phy_To_Virt()` 转换。
- **日志规范**：全部使用 `log_info("[xhci] ...")`/`log_err("[xhci] ...")`/`log_warn("[xhci] ...")`，禁止裸用 `serial_printk`/`color_printk`。
- **PCI 使能规范**：在访问 MMIO 和 DMA 前必须先调用 `pci_set_bus_master(pdev, true)` 与 `pci_set_decode(pdev, false, true)`，并在出错或注销时成对还原。
- **硬件规范约束**：
  - Command Ring 单页 256 TRBs，TRB 255 必须为 Link TRB（Type 6, TC=1, 目标为 `cmd_ring_phys`）。
  - Event Ring 使用硬件 ERST 计数器，严禁包含 Link TRB。
  - ERDP 写入必须包含 `| (1ULL << 3)`（EHB 位）清除忙状态。
  - 必须严格执行五步复位握手，禁止在 `HCH==0` 时写 `HCRST`。
  - 解析 `HCSPARAMS2`，若 `max_scratchpads > 0` 在阶段一打印警告并返回 `-ENOTSUP`。
  - 写入 `CONFIG.MaxSlotsEn = min(ctrl->max_slots, 16)`。
  - Interrupter 0 写入 `IMAN.IP` (bit 0, RW1C) 清除待决中断，同时置 `IMAN.IE = 0`。

## Review Focus

1. 硬件轮询超时控制（500ms 约束与 `USBSTS.HSE` 检测），避免硬件挂死导致内核启动死锁。
2. Command Ring Link TRB 的 Cycle Bit 软硬件流转一致性（`enqueue == 255` 时的翻转与回绕）。
3. 异常路径下的 DMA 物理页释放完整性（`xhci_free_dma` 是否无内存泄漏）。
4. MMIO 虚拟地址与物理地址区分，在宿主测试下使用 `#ifndef OS01_HOST_TEST` 防护内核专有页表映射。
5. 宿主单测链接真实的 `pci_core_production.o`，绝不重复定义 `pci_bar_window`，通过 `dev.bars[0]` 填充与 `arch_pci_backend` 驱动。
